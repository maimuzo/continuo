## 実装を始める前に、計画をレビューしてください

**実装の計画を書いたら、そのまま実装に入らないでください。**

1. **`code-reviewer` の subagent に計画をレビューさせてください**
2. **指摘を全部直そうとしないでください。**1件ずつ「直すのが妥当か」を判断してください
3. **判断票を issue のコメントに残してから**、実装に入ってください

**Critical と High は原則すべて直してください。**直さない場合は理由を書いてください。
**指摘が1件も無かったときは、判断票を書かないでください。**

**判断票の形。**

    | 変数名の揺れ | Low | repoDir と repoPath が混在 | 直さない | この issue の範囲外 |

## PR を作ったら、レビューしてください

**PR を作ったら、そのまま人間へ渡さないでください。**

1. **`code-reviewer` と `security-reviewer` の subagent にレビューさせてください**
2. **指摘を全部直そうとしないでください。**1件ずつ「直すのが妥当か」を判断してください
3. **上と同じ形で判断票を issue のコメントに残してから**、直してください
