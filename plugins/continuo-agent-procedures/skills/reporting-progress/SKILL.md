**<進捗の間隔（分）>分以上、コメントを書かないまま作業を続けません。**途中経過のコメントの先頭は `<!-- continuo:agent -->` と `<!-- continuo:progress -->` の2行で、行の先頭から書きます。書く前に担当を確かめます。
途中経過の印は、最後の成果報告（「finishing-run」の「runの終了を宣言する」）の先頭には付けません。
システムプロンプトの値に `<マージンのファイル>` があれば、時刻を確かめるとき・subagent を起動する前・長いコマンドを叩く前にマージンを確かめ、切っていたら下の「レートリミットのマージンを切ったら、切り上げる」の段2 で切り上げます。

## <進捗の間隔（分）>分以上黙らない

<進捗の間隔（分）>分以上、コメントを書かないまま作業を続けません。区切りのいいところで、いま何をしているかを issue のコメントに残します。
`<!-- continuo:progress -->` の付いたコメントが担当の期限のあいだ現れないと、担当が外れて別の機械が入札をやり直し、push していない変更は他の機械から見えなくなります（書き足しでも期限の時計は進みます）。

### 時刻を確かめる

あなたは時間が経ったことに自分では気づけません。長い作業に入る前に叩いて時刻を控え、区切りごとにもう一度叩きます。控えた時刻から<進捗の間隔（分）>分を超えていたら、担当を確かめてから段1へ進み、書いたら時刻を控え直します。

```bash
date '+%Y-%m-%d %H:%M (%Z)'
```

### 担当を確かめる

書く前に、「starting-run」の「分岐元を取り込み、読む」の見本で担当を確かめます。見本はスクリプトになっています（引数は `<issue の URL>` の1つ）。

```bash
sh 'CONTINUO_PLUGIN_DIR/skills/starting-run/scripts/check-assignee.sh' '<issue の URL>'
```

| 出た文 | すること |
| --- | --- |
| 「担当は自分です」「担当者がいません」 | 段1へ進みます |
| 「止まります」 | 途中経過のコメントも push もせず、「starting-run」の「分岐元を取り込み、読む」の段1 の表のとおりに止まります（「finishing-run」の「runの終了を宣言する」の報告は書きます） |
| 「確かめられませんでした」 | 途中経過のコメントは書き、今回の push だけを見送って作業を続けます。次の push の前に確かめ直します |

### 段1. いちばん下のコメントが、自分の進捗報告かを見る

コメントは増やさないでください。いちばん下が自分の進捗報告ならその1件に書き足し、そうでなければ新しく1件投稿します。

```bash
gh issue view <issue の URL> --json comments \
  --jq '.comments[-1:][]
        | select(.viewerDidAuthor
                 and (.body | startswith("<!-- continuo:agent -->"))
                 and (.body | contains("<!-- continuo:progress -->")))
        | .url | split("#issuecomment-")[1]'
```

| 返ったもの | すること |
| --- | --- |
| 数字が1つ | それが書き足す先のコメントの ID です。段2a へ進みます |
| 何も返らない | いちばん下は自分の進捗報告ではありません（人間か別の機械が書いたか、まだ1件も書いていません）。段2b へ進みます |

### 段2a. その1件に書き足す

```bash
sh 'CONTINUO_PLUGIN_DIR/skills/reporting-progress/scripts/append-progress.sh' append '<issue のリポジトリ>' '<段1が返した数字>' <<'NOW'
<いま何をしていて、あと何が残っているか>
NOW
```

- 引数は、`append`・`<issue のリポジトリ>`（`owner/repo` の形）・段1 が返した数字の3つです。標準入力に `<いま何をしていて、あと何が残っているか>` を渡します。
- スクリプトは、行頭に `- <いまの時刻> いま ` を付けた1行を作り、そのコメントの本文を読み直して、`<!-- continuo:progress -->` があるときだけ、本文の後ろへその1行を足して書き換えます。書き換えたときは `gh api` が返した JSON が出ます。
- 「本文を読めませんでした。段2b で新しく1件投稿します」と出たら、段2b へ進みます。
- 引数か標準入力が足りないときは、何も書き込まずに、使い方を標準エラーへ出して終了コード 2 で終わります。

**`case` で印そのものを確かめてから書き込みます**（スクリプトの中でそうしています）。`gh api` は取得に失敗するとエラーの JSON を標準出力へ出すので、空でないかを見るだけでは足りません。
そのまま書き込むと印ごと本文が消え、continuo は担当の期限の時計を担当を取った時刻（hold のコメント）まで巻き戻し、次の巡回で担当が外れることがあります。

### 段2b. 新しく1件投稿する

```bash
sh 'CONTINUO_PLUGIN_DIR/skills/reporting-progress/scripts/append-progress.sh' new '<issue の URL>' <<'NOW'
<いま何をしていて、あと何が残っているか>
NOW
```

- 引数は、`new` と `<issue の URL>` の2つです。標準入力は段2a と同じです。
- スクリプトは、次の形の本文をファイルへ書いてから `gh issue comment <issue の URL> --body-file` で投稿します。投稿したコメントの URL が出ます。

```markdown
<!-- continuo:agent -->
<!-- continuo:progress -->
まだ作業中です。

- <date '+%Y-%m-%d %H:%M (%Z)' が出した時刻> いま <標準入力に渡したもの>
```

- 印の2行は、見本のとおり行の先頭から書き、字下げしません（スクリプトはそう書きます）。字下げすると印が本文の中の引用とみなされ、このコメントがこの run の成果の報告として数えられます（最後の報告を書かずに終えても、continuo は書き直させません）。
- 2行目の `<!-- continuo:progress -->` を落としません。continuo が「進捗が書かれた」と数えるのは、この印が付いたコメントだけです。落とすと次の段1が見つけられずにコメントが増え、期限が来ると担当が外れて、別の機械がこの issue を最初からやり直します。
- `<いま何をしていて、あと何が残っているか>` は `<<'NOW'` の下に書き、二重引用符の中へ書きません。backtick や `$` をシェルが実行します（段2a も同じです）。
- この印を、最後の成果報告の先頭には付けません。付けると continuo はその報告を数えず、セッションを復元してもう一度書かせます。本文の途中で引用するのはかまいませんが、囲み付きのまま引用すると、次の進捗報告がその成果報告へ書き足してしまいます。

### 段3. push する

push できる状態なら、あわせて push します（push の前の commit と担当の確かめは「implementing-and-pushing」の「commit して push する」）。

```bash
git push -u origin HEAD
```

push が通って、この branch の pull request がまだ無ければ、「implementing-and-pushing」の「pull request を出す」のとおりに draft で作ります。途中で止まっても、次に引き継ぐ機械が pull request を辿れます。

## レートリミットのマージンを切ったら、切り上げる

**システムプロンプトの値に `<マージンのファイル>` が無ければ、この節は当たりません。**

利用者は、自分で Claude Code を使うぶんとしてレートリミットの一部（マージン）を残しています。そこへ食い込んだら、作業の途中でも切り上げます。

### 段1. マージンを切ったかを確かめる

区切りごと（上の「<進捗の間隔（分）>分以上黙らない」で時刻を確かめるとき・サブエージェントを起動する前・長いコマンドを叩く前）に叩きます。continuo が判定した結果を、このファイルへ1行で書いています。

```bash
cat '<マージンのファイル>'; date +%s
```

| 出たもの | すること |
| --- | --- |
| 1行目が `MARGIN: cut` で始まり、その中の `expires_at=` の数が2行目の数より大きい（どちらも UNIX 時刻の秒） | 段2へ進みます |
| それ以外（`MARGIN: ok`・`MARGIN: unknown`・ファイルが無い・読めない・`expires_at=` を過ぎている） | そのまま作業を続けます |

continuo から「レートリミットのマージンを切りました」という指示が届いたときも、段2を行います。済んでいれば、何もせずに `CONTINUO-STATUS: working` で終えます（表明の1行の書き方は「finishing-run」の「runの終了を宣言する」）。

### 段2. 切り上げる

1. 新しいサブエージェントは起動しません。走っているサブエージェントは止めません
2. **先に、いまある変更を commit して push します**（「implementing-and-pushing」の「commit して push する」）
3. 走っているサブエージェントの結果が返ったら、その分も commit して push します
4. どこまで進んだか・次に何をするかを、issue のコメントに書きます。このコメントは、その run の何をしたかの報告に当たります。印は「finishing-run」の「runの終了を宣言する」と同じ1行（`<!-- continuo:agent -->`）で、「writing-comments-for-humans」の「人間へ質問・報告するコメントの書き方」の8つの見出しで書きます。「finishing-run」の「runの終了を宣言する」の段3 の、「issue を読む」と「紐づく pull request を読む」の読み直しと、「finishing-run」の「まとめて直したとき」は省いてかまいません
5. 応答の最後に `CONTINUO-STATUS: working` を書いて終えます。人間へ戻すか別の機械へ引き継ぐかは、continuo が決めます
