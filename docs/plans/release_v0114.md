## 3. 破壊的変更（4つ）

**案内の正は [docs/upgrading.md](../upgrading.md) の「v0.1.13 から v0.1.14 へ」である。ここには写さない。**
**ここに置くのは、何が壊れるかの一覧だけである。**

| 何が変わったか | 何もしないとどうなるか |
| --- | --- |
| **`runtime` の節（`runtime.lock_file`）が無くなった**（PR #112） | **起動しない。**`WORKFLOW.md` から `runtime:` の2行を消す必要がある |
| **本文に書いた `<!-- … -->` が送られなくなった**（PR #203） | **起動はする。**ただし**コメントで書いた決まりが、エージェントへ届かなくなる** |
| **雛形の `## PR を作るか` が `## PR の決まり` に変わった**（PR #185） | **起動はする。**エージェントが pull request を作るようになる |
| **進捗報告の数え方が変わった**（PR #202） | **起動はする。**版を上げた時点で走っている issue は、**進捗報告が1件も無いように見える** |

**入れ替えの前に、走っている issue を終わらせること。**
**同じカンバンを複数の機械で見張っている場合はとくに要る**（[docs/upgrading.md](../upgrading.md) の同名の節）。

## 4. この版で決めたこと

**設計そのものを変えた判断だけを置く。**手順の話は置かない。

| 何を決めたか | なぜそう決めたか |
| --- | --- |
| **破壊的変更を許容する** | **人間の判断である**（2026-09-03）。「既存ユーザを気にして変な設計にするより、理想の形を目指せ」。**`runtime.lock_file` を受け取って捨てる案を捨て、キーごと消した** |
| **巡回が continuo 自身の書いた Status に反応しない門を置く**（設計 3-74c） | **後片付け8つが飛ぶ窓が実在した。**`finishRunClaimed` と `stopAndReleaseAsync` が権利を取り合い、**巡回が先に取ると、ログを1行も残さずに run が消える** |
| **`WORKFLOW.md` の本文にだけ、空になった見出しを落とす処理を当てる**（設計 5-3m） | **継ぎ合わせた全文に当てると、組み込みの `## 4-4` が消える。**そこは「ここから先は利用者が書いたもの」という唯一の区切りである |
| **進捗報告の間隔の下限を 60000（1分）にする**（設計 5-3n） | **送る文面へは分に直して埋める。**59999 までは全部「0分以上黙らない」になり、**エージェントは書けない指示を受け取る** |
