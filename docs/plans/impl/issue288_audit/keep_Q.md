## 3. 迷ったもの

- M1（人間に訊くべき）: 798-802 の「draft を外さない3つの場合」。PR #303 の本文に「人間に確かめている途中のこと」として、例外1・2（10周で止まった・打ち切った）と例外3（WORKFLOW.md に「draft のまま」とあるとき）が AI の読みとして書かれている。人間が了承したコメントは見つけられなかった。了承済みなら原則4で残す。了承が無いなら原則には当たらず、移すことになる。ただし移すと、スキルを呼ばない run は CRITICAL か HIGH が残った pull request の draft を外しうる。
- M2: 848-849 の「`gh pr checks` に `--json` を付けない」。付けると赤でも終了状態が 0 になり、通ったと読んで報告する。取り消せない害（原則2）とまでは言えないので移すとした。人間がこれを原則2として扱うなら残す。

  - 案A（この一覧のとおり）: 人間の指示の文と表をそのまま残し、理由・見本・言い直しだけ移す。
  - 案B: システムプロンプトには「話題ごとに節、節の中は 引用・三行まとめ・前提・単語の説明・既存の構造・何が問題なのか・詳細 の順、図は具体的な値、技術用語は英語、質問は1問1節で表で訊かない、1 run 1 コメント（例外は計画・報告・途中経過・判断票・7-2）」を3〜4行に縮めて残し、1126-1132 の理由の列と 1166-1174 の中身の列はスキルへ移す。原則4の「決まり」は残り、説明だけが移る。
  - 推奨は案B。決まりそのものは落とさず、システムプロンプトを約1,000トークン軽くできる。
- M4: 751-752 と 3-2 の 405-407行が同じことを書いている（`KIND=実装`・`PR=`・`PRREPO=`）。3-2 の担当がどちらへ振るかに合わせて、片方へ寄せたい。
