# 設定を、continuo を止めずに読み直す（まず4キーだけ）

**対象。**#224（continuo を止めずに WORKFLOW.md を読み直せない（worker が走っていると再起動をためらう））。

**この文書が正である。**[docs/plans/continuo_design.md](../continuo_design.md) の 3-24 を、この1件の範囲で具体化したもの。
**3-24 は残す。置き換えない。**

---

## 1. 言いたいこと

**言いたいこと。**`WORKFLOW.md` の全81キーのうち、**走行中に差し替えるのは4キーだけである。**
残る77キーと本文は凍結し、変わっていたら「効きません」と知らせる。
**広げるときは1キーずつ、別の issue で2つの判定を通してから足す。**

**なぜ4キーか。**設計レビューを4周かけ、**広く効かせる案が Critical で潰れたためである。**

| 周 | 決定的だった指摘 |
| --- | --- |
| 1 | 読み直しで作り直す派生値（`knownStateNames` と送るプロンプト）が、巡回と run の両方の goroutine から読まれるので data race になる |
| 1 | 枠の読み取り役へ差し替えを配ると、`token_source` を変えたときに資格情報の置き場所が空のままになり、**その機械が1件も処理しなくなる** |
| 2 | **新しい Status 名を差し替えると、カンバンのアダプタが選択肢 ID を持っていないので Status を書けなくなる**（`tracker.verify_states_every` の周期まで直らない。0 なら永久） |
| 2 | **古い設定と新しい設定を混ぜた結果は、どちらのファイルとしても存在せず、検査を1度も通っていない** |
| 3 | 対応表の綴りの検査へ新しい値を渡す案は、**前提が実在しなかった**（`VerifyStatusOptions` は `missingRewriteKeys` を呼んでいない）。削除した |
| 3 | **本文を直しても1行も出ない。**本文は `Config` の外にあるので、設定の差分には出てこない |

## 2. 差し替える4キー

| キー | 何を決めるか | 読み出し箇所 |
| --- | --- | --- |
| `tracker.provider.handoff.on_assignee_gate` | 担当者が付いていて着手できないとき、issue へ案内を書くか | [internal/orchestrator/gate.go](../../../internal/orchestrator/gate.go) |
| `tracker.automated_state_rewrite` | カンバンの自動化が動かした Status を、どこへ戻すか | [internal/orchestrator/unknownstate.go](../../../internal/orchestrator/unknownstate.go) の3箇所 |
| `agent.max_concurrent_agents` | 同時に走らせる Claude Code の数の上限 | [internal/orchestrator/dispatch.go](../../../internal/orchestrator/dispatch.go) |
| `agent.max_concurrent_agents_by_state` | Status ごとの上限 | 同上 |

**下2つは1組で扱う。**空なら全体の上限へ落ちる決まりなので、片方だけを差し替えられるようにすると、
**同じ判定の5行の中で出どころが2つになる。**

### 足してよいかの判定は2つ

| # | 判定 | 通らないとどうなるか |
| --- | --- | --- |
| **1** | **新しい Status 名を持ち込まないこと** | カンバンのアダプタは Status の選択肢 ID を起動時に焼き込む。新しい名前を入れると Status の書き込みが必ず失敗する |
| **2** | **走っている run が、その値を前提に外部へ既に何かを書いていないこと** | 例: `tracker.comments.marker` はエージェントへ渡すプロンプトに埋まっているので、変えると成功した run が `failure_state` へ落ちる |

**`claude.hook_bridge.listen` を入れてはならない。**起動時に socket のパスへ解決され、
issue ごとの設定ファイルへ書き込み済みである。**入れると、動いている Claude Code の hook の宛先と本体が食い違う。**
**この禁止はテストで機械的に止めている**（[test/internal/config/reload_test.go](../../../test/internal/config/reload_test.go)）。

## 3. どうやって差し替えるか

**`Orchestrator` が持つ設定（`cfg`）は差し替えない。**
多数の goroutine が錠なしで読んでおり、`[]string` や `map` を持つので代入が不可分でないためである。
**4キーだけを `atomic.Pointer` で別に持つ**（[internal/orchestrator/orchestrator.go](../../../internal/orchestrator/orchestrator.go) の `reloadable`）。

- **143行156箇所の書き換えが要らない**
- **[internal/orchestrator/settings.go](../../../internal/orchestrator/settings.go) を触らない**ので、hook のコマンド行にも issue ごとの設定ファイルにも影響しない
- **同じ形が既にある。**[internal/i18n/i18n.go](../../../internal/i18n/i18n.go) が `atomic.Pointer[Catalog]` で同じ問題を解いている

## 4. 読み直しの段取り

**`Tick` の頭で1回だけ行う**（[internal/orchestrator/reload.go](../../../internal/orchestrator/reload.go)）。

| 順 | 何をするか | 失敗したら |
| --- | --- | --- |
| 1 | 設定ファイルのパスが空なら何もしない | — |
| 2 | 更新時刻・大きさ・中身のハッシュを取る | **何も言わずに次の巡回へ回す**（エディタの書き換えの最中は一時的に読めない） |
| 3 | 前の印と同じなら何もしない | — |
| 4 | 読み直す | WARN を出して古いまま続ける。**印は進める** |
| 5 | 4キーだけを上書きし、**混ぜた結果へ検査を掛け直す** | 同上 |
| 6 | 効かなかった項目を並べる（本文の変化も1件として混ぜる） | 差分を作れなくても差し替えは行う |
| 7 | 差し替える。効いた項目を INFO、効かない項目を WARN で出す | — |

**段4 と段5 で印を進めるのは、壊れたファイルを30秒ごとに読み直して同じ WARN を流し続けないためである。**
人が直せば印が変わるので、次の巡回で読み直す。**同じ理由の警告は出し直さない。**

**読み直しは、ファイルへ1バイトも書かず、外部プロセスを1つも起こさない。**
だから**失敗しても既存の状態を1バイトも触らない。**

## 5. 上書きの向き

**いま効いている設定を土台に、差し替えてよい4キーだけを新しい設定から写す。**

**逆にしてはならない。**「凍結するキーを古い設定から書き戻す」形にすると、
**書き漏らしたキーが「効く」側へ落ちる。**設定にキーを足した人がここの更新を忘れると、
走っている run の前提を壊す側で黙って動く。
**この向きなら、書き漏らしは「変わらない」側へ倒れる。**

## 6. 効かなかった項目の報告

**混ぜた結果と、読み直したファイルの両方を YAML へ落として `map` に戻し、キーの道筋をたどって比べる。**

| なぜこの形か | 中身 |
| --- | --- |
| **キーごとのコードが1行も要らない** | 77キーぶんの比較を手で書くと必ず漏れる。設定にキーを足しても報告は自動で追随する |
| **ドット区切りのキーが出る** | 葉の名前だけでは足りない（`max` / `order` / `timeout_ms` は2箇所以上ある） |
| **map の並び順に依存しない** | キーで引き当てて比べる |
| **`reflect` を使わない** | 本体は `reflect` を1度も使っていない |

**`claude.env` は、キーの名前だけ出して値を伏せる。**利用者がそこへ鍵を置くことがあり、
**前後の値を出すと、ログを貼り付けただけで外へ出る。**

**本文だけは「前後の値」ではなく「変わりました」と出す。**中身は長く、何が書いてあるか分からない。
**受け入れ条件の「前後の値」に対する、意図した例外である。**

## 7. 案内を「書かない」と決めた記録を捨てる

`tracker.provider.handoff.on_assignee_gate` が変わった読み直しでは、
**「設定で書かない」と決めた記録だけを捨てる**（[internal/orchestrator/gate.go](../../../internal/orchestrator/gate.go) の `forgetGateNoticesOffByConfig`）。

**理由は、ダッシュボードに文言として出ているからである。**
捨てないと、`warn_and_comment` へ戻したあとも画面が「設定で書きません」という**いまは嘘になった説明**を出し続ける。

**「読み直しが再起動より弱い」だけでは理由にならない。**同じ弱さは書き戻しの回数にもあり、
そちらは直していない。**違いは、こちらだけが画面に出ていることである。**

## 8. 読み直しでは出ないもの

| 何 | どうなるか |
| --- | --- |
| **対応表の綴りがカンバンに実在するかの警告** | **出ない。**起動時（`Bootstrap`）にしか出ない。出したければ再起動する |
| **対応表が効く時間の窓** | **読み直しで救えるのは、その run がまだ止まっていないあいだだけである。**猶予の既定は10分（`tracker.unknown_state_grace_ms`） |
| **案内文の組み合わせ** | 読み直したあとの案内文は、新しい対応表と凍結した `active_states` を混ぜて作る。**混ぜた結果を検査し直しているので、不整合な組は弾かれる** |
