# レビューの周回の実測

**言いたいこと。**実装レビューの周回は、PR 1本の中で数え直しをまたいで足すと最大36周、issue 1件の設計＋実装では最大62周だった。20周を超えた issue は22件中6件あり、人間の「20回ぐらい」は控えめな見積もりである。
周回の多い5本の Critical と High 217件では、いちばん多い原因が修正漏れ（52件、24.0%）で、写しの食い違いと参照のずれを合わせた「同様の箇所を確かめていれば防げた」群が74件（34.1%）。次は「直しが新しく生んだ」49件（22.6%）と「直さないと決めたものが残り続けた」35件（16.1%）。
周回の多い上位2本では、周が進んでも High が1〜7件の間を上下して減らず、1周目の件数と総周回数の関係も弱い（順位相関 0.18）。

## 5. 数え方の限界と、CI との違い

**CI との違い。**
- 目印の正規表現と投稿者の条件は、CI と同じである
- CI の jq の式をそのまま取得結果へ掛けても、337件と141件で一致した。jq の `test("^…")` は行頭ではなく本文の先頭にだけ当たることを、3つの本文で確かめた
- 違うのは数える範囲と時点である。CI はイベントのたびに、その PR（設計は閉じる issue）のコメントだけを、その時点の本文で数える。この集計は 2026-09-15 時点の全コメントの本文を数えた
- そのため、あとから編集・削除されたコメントは、CI が見たものと食い違いうる

**件数の表の行を拾う数え方にしない。**
- 「| High | 1 | 0 | 0 |」のような件数の表の行も指摘と数えると、1周目の C+H と累計の順位相関は 0.309 になる
- 実例は PR #221 の3周目で、実際は0件のところを2件と数えていた
- この報告の件数は、「レベル」の列を持つ指摘の表の行だけを数えたものである

**測っていないこと。**
- 全111本の、周ごとの Critical / High / Medium / Low（表の書式がばらばらなので、上位5本だけ数えた）
- Medium と Low の分類
- diff による分類の確かめ（PR #230 の commit 6つの存在と題名だけは確かめた）
- 「分類」の列の決まりで読み替えたときの件数。[CLAUDE.md:516](../../../../CLAUDE.md#L552) の「分類」の列は、commit を示せない「直しが持ち込んだ」を「前の周に既に在った」として扱うと決めている。この報告は実装者の分類に従った。「直しが持ち込んだ」21件のうち、どの周のどの直しかを本文で名指ししていないものは7件ある。それを読み替えたときの数は出していない
- 表に載っていない C/H（PR #230 の系列4の4・5周目、PR #220 の系列1の3〜6周目と系列2の1〜4周目）
- 規則が足された日の前後の差（1-4 の理由による）
- Agent で立てたレビュワーの種類を、セッションのログから数えること
