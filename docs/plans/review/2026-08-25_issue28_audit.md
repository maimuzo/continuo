# 監査 2026-08-25（issue #28 壊れた ref の始末）

**言いたいこと。**12件の指摘を全部直した。**いちばん重いのは「`.git` の外の任意の1ファイルを
消せる」経路**で、封じ込めがパスの文字列比較だけだったことが原因である。
**「消した」と答えたのに branch が残る**（packed-refs の復活）も直した。

**設計は [3-22b](../continuo_design.md) と [3-22c](../continuo_design.md) に置いた**
（消してよい条件と、消したあとに確かめること）。

## 指摘と対応

| 短縮名 | 何が問題だったか | どうしたか |
| --- | --- | --- |
| **refs/heads の外へのリンク抜け** | 封じ込めがパスの文字列比較だけで、途中のシンボリックリンクを解決しない | **直した。**`resolvedPathUnder` が親を `filepath.EvalSymlinks` で解決してから比べる |
| **packed-refs の復活** | loose を消すと packed 側が生き返るのに「branch を消した」と答える | **直した。**`confirmBranchGone` が存在を確かめ直し、生き返っていたら1回だけ撃ち直す |
| **detached の取り違え** | detached HEAD の worktree でも現物との照合を飛ばしていた | **直した。**`detached` の行で見分け、worktree の `HEAD` の symref で裏を取る |
| **lock ファイルの巻き添え** | `<名前>.lock` を「壊れた ref」と読んで消しうる | **直した。**`git check-ref-format` を先に通す（**指摘の前提は誤り。**下の節を見よ） |
| **検査と削除のあいだの割り込み** | 判定と削除のあいだに正常な ref が置かれると、それを消す | **直した。**判定時の大きさと最終更新時刻を控え、消す直前に読み直して突き合わせる |
| **掃除が壊れた ref を見ない** | `git for-each-ref` が壊れた ref を出さないので、起動時の掃除が1度も動かない | **直した。**`refs/heads` の下を実ファイルとして歩く。worktree が使う branch は `HEAD` から読んで除外する |
| **消す前の commit を控えない** | 消したあと戻す手掛かりが1つも残らない | **直した。**reflog のファイルから最後の SHA を読み、戻せるコマンドを添える |
| **abandon に記録が残らない** | 消したことが `io.Discard` の logger にしか行かない | **直した。**`CleanupResult.Notices` に積み、`continuo abandon` が画面へ出す |

## テストの守りが無かった4件

**言いたいこと。**指摘のとおり、**守りを外してもテストが1本も落ちない**状態だった。
**4件とも、外すと落ちる形の検査を足してある**（[test/internal/workspace/brokenref_test.go](../../../test/internal/workspace/brokenref_test.go)）。

| 短縮名 | 足した検査 |
| --- | --- |
| **正常な branch の守り** | `TestPrepare_正常なbranchのrefは消さない`。別の worktree で commit を積み、元の worktree が `git log` に答えられることとファイルの中身の一致を見る |
| **接頭辞一致の守り** | `TestPrepare_接頭辞と食い違うbranchのrefは消さない`。テンプレートを `continuo:{{.issue.number}}` にして接頭辞と正規化後の名前をずらす |
| **commit に解決できる ref の守り** | `TestPrepare_commitに解決できるrefは消さない`。実在しない object の40桁を置き、`show-ref` が落ちて `rev-parse` が通ることを先に git に言わせる |
| **通常のファイル判定** | `TestPrepare_refがシンボリックリンクなら消さない`。リンクとリンク先の両方が残ることを見る |

## 守りが本当に効いているかの確かめ方

**言いたいこと。**「テストが通る」ではなく、**守りを1つ外したら落ちるか**で確かめた。
`go test -overlay` で判定を1つずつ潰した版を作り、どのテストが落ちるかを見た。

| 外した守り | 落ちる検査 |
| --- | --- |
| シンボリックリンクの解決 | `TestCleanup_途中がシンボリックリンクなら外のファイルを消さない` |
| 中身が読めるかの判定 | `TestPrepare_中身がSHAとして読めるrefは消さない` |
| worktree の `HEAD` による裏取り | `TestCleanup_HEADが指していないbranchの壊れたrefは消さない` |
| packed-refs の確認 | `TestCleanup_packedrefsから生き返るbranchを片付けたと答えない` |
| 掃除の `HEAD` による除外 | `TestSweep_worktreeが使っている壊れたrefは消さない` |
| 掃除の `refs/heads` 歩き | `TestSweep_壊れたrefも掃除する` |

**外しても落ちない守りが2つある。**どちらも意図して残した。

| 守り | なぜ検査で捕まえられないか |
| --- | --- |
| `git check-ref-format` | 正規化（`internal/normalize`）が先に `.lock` を弾くので、**2枚のうち1枚を外しても通る。**両方を外すと `TestCleanup_lockファイルは壊れたrefとして消さない` が落ちる |
| 判定と削除のあいだの読み直し | 別プロセスの割り込みを、テストから決まった順序で起こす手立てが無い。**踏ませて再現はしていない** |

## 指摘の前提が誤っていた1件

**言いたいこと。**「lock ファイルの巻き添え」の指摘は
**「`normalize.SafeName` はドットを許すので `188.lock` は正規化で変わらない」**を前提にしていたが、
**正規化は `.lock` で終わる要素を `_lock` に変える。**

根拠は [internal/normalize/normalize.go:166-168](../../../internal/normalize/normalize.go#L166-L168) である。

```go
if strings.HasSuffix(seg, ".lock") {
	// `.lock` で終わる要素は拒まれる（git が使う拡張子である）。
	segments[i] = seg[:len(seg)-len(".lock")] + "_lock"
}
```

身元ファイルの検算も掃除も「正規化で変わる名前は使わない」を通すので、
**`.lock` を指す経路は元から閉じていた。**それでも `git check-ref-format` を足したのは、
正規化を通らない経路が将来できたときに、そこで止まるようにするためである。

## 実測（git 2.50.1、macOS）

**言いたいこと。**設計に書いた git の振る舞いは、全部この版で確かめた値である。

| 何を置いたか | `show-ref` | `rev-parse` | `check-ref-format` |
| --- | --- | --- | --- |
| 0バイト | 失敗 | 失敗 | 通る |
| 実在しない object の40桁 | 失敗 | **通る** | 通る |
| 64桁の16進（SHA-1 のリポジトリ） | 失敗 | 失敗 | 通る |
| `<名前>.lock`（空） | 失敗 | 失敗 | **失敗** |

**`git pack-refs --all` のあとに loose を壊して消すと、packed 側の ref が生き返る。**
そのとき branch は packed-refs が指す commit まで巻き戻り、あいだの commit は branch から外れる。
