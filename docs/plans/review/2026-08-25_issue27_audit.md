# 変異検査で見つかった穴に足したテスト（2026-08-25）

**言いたいこと。**production を1箇所ずつ壊して `go test -overlay` で走らせ、
**1本も落ちなかった守りが5つあった。**そこへテストを5本足し、
**同じ壊し方で必ず落ちること**を実測で確かめた。リポジトリのファイルは変異では書き換えていない。

## 足したテストと、塞いだ守り

| 短縮名 | 塞いだ守り | 足したテスト |
| --- | --- | --- |
| **branch 名に番号必須** | `branch_template` に `.issue.number` が無い設定を起動前に弾く | `TestValidate_branch_templateにissueの番号が無ければ弾く` |
| **番号があれば通す** | 番号さえ入っていれば並べ方は自由（効きすぎの防止） | `TestValidate_branch_templateにissueの番号があれば通す` |
| **調べられないと無いは別** | `git show-ref` の終了コード 128 を「branch は無い」に丸めない | `TestFindIssueBranch_リポジトリが壊れていれば無いと言わない` |
| **prune の撃ち分け** | 実体の無い登録がほかにもあるときは `git worktree prune` を撃たない | `TestCleanup_実体の無い登録がほかにもあればpruneを撃たない` |
| **prune を撃つ側** | 自分が消した1件だけなら撃つ（守りが効きすぎる方向の壊れ） | `TestCleanup_自分が消した1件だけならpruneを撃つ` |
| **一覧を引けないとき** | 登録の一覧を引けなければ撃たない（`staleErr` の枝） | `TestCleanup_登録の一覧を引けなければpruneを撃たない` |

## アサーションの置き先

**言いたいこと。**prune の3本は、残ったものの文言だけを見ない。
**`git worktree list --porcelain` の実物**を引いて、登録が落ちたかどうかを直接見る。
文言だけを見ると、prune が撃たれたかどうかを取り違える。

| 何を見るか | 撃っていないときの姿 |
| --- | --- |
| `git worktree list --porcelain` | 移された worktree の登録も、消した worktree の登録も残っている |
| `CleanupResult.Leftovers` | `workspace.leftover.prune_skipped` / `prune_failed` の文言が入る |

## 変異で落ちることを確かめた壊し方

**言いたいこと。**壊した版は `/tmp/mut/` に置き、`go test -overlay` で差し替えて走らせた。
**4通りの壊し方すべてを、足したテストのどれかが落とす。**

| 壊し方 | 落ちたテスト |
| --- | --- |
| `validate.go` の `.issue.number` の検査を消す | branch 名に番号必須 |
| `gitBranchExists` を `return code == 0, nil` に戻す | 調べられないと無いは別 |
| `cleanup.go` の「ほかにもある」判定だけを外す | prune の撃ち分け |
| `cleanup.go` の判定を丸ごと外して無条件に撃つ | prune の撃ち分け / 一覧を引けないとき |
| `gitStaleWorktreesExcept` を常に「無い」と答えさせる | prune の撃ち分け / 一覧を引けないとき |
| `len(stale) > 0` を `true` にして1度も撃たなくする | prune を撃つ側 |

## 一覧を引けない状態の作り方

**言いたいこと。**リポジトリを壊すと `verifiedRepo` が先に落ちて、この枝へ届かない。
**そこで、1行が 64KiB を超える理由で worktree を lock する。**
`git worktree list --porcelain` 自体は成功するが、continuo はその1行を読み切れない。

```sh
git -C <clone> worktree add -b lock-worktree <パス> main
git -C <clone> worktree lock --reason "<70000文字>" <パス>
```

`git worktree prune` はこの状態でも成功するので、
**「撃たなかった」と「撃ったが失敗した」を登録の残り方で区別できる。**
