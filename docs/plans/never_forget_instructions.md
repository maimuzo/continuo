# 指示を忘れない仕組み

**この文書は何か。**AI が人間の指示を落とさないための仕組みの設計である。
**continuo 本体の設計ではない**（continuo の設計は [docs/plans/continuo_design.md](continuo_design.md) が正）。
**この文書はこのリポジトリでの作業の進め方を決めるものである。**

**検討は issue で続ける。**この文書は、そこまでに決まったことと、決まっていないことを持つ。

> **引用について。**人間の発言は、判断の根拠になった部分だけを引いている。
> **このリポジトリは公開なので、罵倒の部分は落とした。**判断に効いた文は落としていない。

---

## 1. なぜ作るのか

**言いたいこと。**AI は指示を落とす。落としたことに自分で気づけない。
**だから、覚えておく役を機械に持たせる。**

**きっかけになった実例。**2026-08-29、人間が1つの発言で2つのことを言った。

> 同じgithubアカウントでPC複数台使っている人も少数なのでサポート外で良い。必要なら別githubアカウント使うようにFAQ作って。

**決定（サポート外にする）と指示（案内を作る）の両方が入っていた。**
**AI はどちらもやらなかった。**3日後に同じ人間から「サポート外としているはずだぞ」と言われ、
設計を検索して「見つかりません」と答えた。

**人間の指摘。**

> たとえ割り込まれても、アテンションがズレても、指示されたことを絶対に忘れない仕組みを作れ。

## 2. 何を作るか（決まったこと）

**言いたいこと。**AI の判断が入る箇所をすべて機械に置き換える。
**AI が「これは重要だから覚えておこう」と選別する余地を無くす。**

| 順 | 誰が | 何をするか | AI の判断が入るか |
| --- | --- | --- | --- |
| 1 | **機械**（hook） | 人間の発言の全文を記録する | **入らない** |
| 2 | **hook が呼ぶ LLM** | その発言を読んでタスクを抜き出す | **入らない** |
| 3 | AI | 自分でも抜き出して登録する | 入る |
| 4 | **機械** | 2 と 3 の件数を突き合わせる | **入らない** |
| 5 | AI | タスクごとに「完了を確かめるコマンド」を書く | 入る |
| 6 | **機械** | そのコマンドを実行して、閉じてよいかを判定する | **入らない** |

### 2-1. 記録の置き場

**パス。**`<リポジトリ>/.claude/requests/tasks.jsonl`（1行1件の JSONL）

**中身のサンプル**（実際に書かれる形）。

```json
{"id":"20260901T0839-1","at":"20260901T0839","what":"worktree が別の branch を出す件を直す","quote":"今作ったリリースだって、まだissueの内容が治ってないと追加issue #142が届いてるぞ。なんで情報あるのに修正できないんだ?","session":"/Users/…/a0d373b0-….jsonl","verify":"grep -c ErrWorktreeBranchMismatch internal/workspace/prepare.go","kind":"once","status":"open","closed_at":"","did":""}
```

**誰がいつ書くか。**hook が呼ぶ LLM が段2で書き、AI が段3で足し、段6で閉じる。

**commit しない。**人間の発言がそのまま入るため、`.claude/requests/` を `.gitignore` へ入れる。

**書き換えは一時ファイル + `os.replace` で差し替える**（CLAUDE.md の絶対条件4）。

### 2-2. タスクの識別子は「発言の時刻 + 連番」

**例。**`20260901T0839-1`

**文面では特定しない。**「忘れた原因を説明する」のような同じ文面のタスクが何度も登録されるため。

### 2-3. タスク1行が持つもの

| 何 | なぜ要るか |
| --- | --- |
| `what`（文面） | 一覧で読むため |
| **`quote`（元の発言の原文）** | **文面は要約であり、要約は文脈を落とす。**落ちた文脈はここにしかない |
| **`session`（そのセッションの jsonl のパス）** | 原文を辿り直すため |
| `verify`（完了を確かめるコマンド） | 機械が閉じてよいかを判定するため |
| `kind`（`once` / `standing`） | 継続して効く規則は閉じないため |

**`quote` が取れないものは、そう書く。**「（別セッションの発言。原文は未取得。**取り直すこと**）」と入れ、空欄で誤魔化さない。

### 2-4. 閉じる条件は2つとも要る

1. **`--did`（何をしたか）が空でないこと**
2. **登録時に書いた `verify` のコマンドを機械が実際に実行し、結果が0件でないこと**

**閉じるのは AI ではなく機械である。**

### 2-5. タスクは2種類

| 種類 | 例 | 閉じ方 |
| --- | --- | --- |
| **`once`** | 「#142 を直す」 | コマンドで確かめて閉じる |
| **`standing`** | 「指示が無いときは workflow + worktree で並列に進める」 | **閉じない。**memory に書いた時点で記録済みとし、一覧の別枠に置く |

### 2-6. 抽出には直前の数発言も一緒に渡す

**発言を単独で渡さない。**

**根拠。**抽出の試験で、サブエージェント自身がこう申告した。
「『サポート外で良い』を拾えたのは、前の発言で叱られているのを一緒に読んだから。
**その発言だけなら承認と読んだ可能性が高い。**」

### 2-7. 抽出は hook が直接 LLM を呼ぶ

**Claude Code の hook には LLM を呼ぶ型が2つある。**

| 型 | 何をするか |
| --- | --- |
| `type: "prompt"` | **1往復でモデルに評価させる。**`model` でモデルを指定できる |
| `type: "agent"` | **`Read` / `Grep` / `Glob` を使えるサブエージェント**（実験的） |

**`UserPromptSubmit` が対応イベントに含まれている。**

出典: [Hooks reference](https://code.claude.com/docs/en/hooks)（2026-09-01 取得）

## 3. まだ決まっていないこと

**言いたいこと。****最重要の穴は「原文1件では足りない」である。**
これが解けないと、AI が完全に忘れたときに復元できない。

### 3-1. 原文1件では足りない（最重要）

**人間の指摘**（2026-09-01）。

> タスクの行に「その指示が出た発言の原文」を持たせるよう直しました。
>
> **足りない。長い会話の流れを全部保存しないと伝わらないこともあるとおもう**

**何が決まっていないか。**

| 何を | 状態 |
| --- | --- |
| **どの範囲の会話を保存するか** | 未決（1発言 / 前後N発言 / その話題の全体） |
| **どう保存するか** | 未決（原文の写し / セッション jsonl の行番号の範囲 / 別ファイル） |
| **どう突きつけるか** | 未決（一覧に全部出すと読めない） |

**この指摘への回答は存在しない。**人間が直後にこのセッションでの議論打ち切りを指示したため。

### 3-2. 登録の中身が雑なとき、件数の突き合わせが通ってしまう

**人間の指摘。**

> 2が長文でタスクが10個混じっていたとして、3では「10個あるか」ではなく「分類してtodoとして登録したか」しか見ないんでしょ?
> それでも、無いよりはマシだけど、不安ではあるな。結局割り込みが忙しくてタスクを忘れるんじゃない?

**AI が出した緩和策**（人間の承認は得ていない）。
「まとめた1件には確かめ方が1つしか書けないので、確かめ方が1つしかないタスクとして次の返答で目立つ」

### 3-3. 抽出に使うモデルが未決

**AI の推奨は Sonnet 5。**「サポート外で良い」のような含意を落とすと、仕組みを作る意味がないため。
**候補。**既定の fast model / `claude-haiku-4-5-20251001`。
**人間の判断は出ていない。**

### 3-4. 完了を機械で確かめられない指示の扱い

**例。**「進捗報告して」「説明し直せ」「なぜそうなった」

**AI 案**（承認は得ていない）。「証拠なしで閉じる。ただし『証拠なし』と記録に残し、あとから数える」

### 3-5. 対象が発言の外にあるタスク

**例。**「重要な仕様をプランへ反映する」の「どの仕様か」は、その発言だけからは特定できない。
**3-1 と同じ根にある。**

### 3-6. AI が「これはタスクではない」と判断して登録しない抜け道

**塞げない。**

**AI 案。**抽出役の出力と AI の登録の差分がファイルに残るので、あとから数えられる
（「抽出役は13件挙げたのに登録は3件」が記録される）。**止める手段ではない。**

### 3-7. くだらない指示をどう外すか

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **選別する** | AI が「追跡不要」と印を付ける | **弱い。**AI の判断が入る |
| **全部記録する** | 閉じるのを軽くする | **AI の推奨。**人間の承認は無い |

### 3-8. 記録の保存期間

**AI 案。**30日で消す（今回の元になった決定は3日前だったので、その程度は残す必要がある）。
**人間の判断は出ていない。**

## 4. 却下した案と、その理由

**言いたいこと。****却下理由を落とすと、次の人が同じ案をまた出す。**

### 4-1. 発言の全文を丸ごと突きつける

**内容。**`UserPromptSubmit` hook が発言の全文を追記し、`Stop` hook が「未完了の指示が3件あります」と丸ごと出す。

**却下の理由**（人間の言葉）。

> チャットで人間が発言することは、明示的なタスクばかりではない。
> 全くタスクに関係ないことも言うし、直前の書き方が悪いから再度説明しろとも言う。
> 1回の長文で指摘を複数することもたくさんあります。同じ問題を何度も別の視点で突っ込むこともあります。
>
> 突きつける部分の構造が理解できない。人間の発言すべてを単純にテキストとして渡すだけでは、
> 結局LLM任せの運用になってうまく回らない

### 4-2. 正規表現で指示らしき文を数える

**内容。**日本語の依頼は文末が決まっている（「〜して」「〜しろ」「〜してください」「〜すべき」「〜するな」）ので、これを数える。

**却下の理由**（人間の言葉）。

> NG。そんな制約は存在しない。もっと複雑だったり表面化しない指示だってあるよ。
> 「どうすればいいかわかるよね?」みたいなのは引っかからないだろ

**実測で裏づけた。**別の LLM に3つの発言を読ませたところ13件を抽出し、**命令形はわずか3件だった。**

| 形 | 件数 |
| --- | --- |
| 依頼形 | 7 |
| 事実の指摘 | 2 |
| 疑問形 | 1 |
| 判断の通達 | 1 |
| **命令形** | **3** |

**「サポート外で良い」は承認の形をしていて、正規表現では絶対に拾えない。**
**それが、今回いちばん高くついた落とし方だった。**

### 4-3. 機械の検査が「AI が登録したか」の1ビットだけを見る

**却下の理由。**長文にタスクが10個混じっていても、1個だけ登録すれば通ってしまう。

### 4-4. タスクを文面で特定する

**却下の理由。**同じ文面のタスクが何度も登録される。文脈により「忘れた原因」は複数あるため、
閉じるときにどれを指しているのか判定できない。

### 4-5. hook からは LLM を呼べないので、AI が Agent ツールで呼ぶ

**却下の理由。****前提そのものが誤りだった。**hook から LLM は呼べる（2-7）。
この案は「呼ぶかどうかを AI が決める」ため AI の判断が入るが、hook が直接呼べばそれが消える。

### 4-6. hook が herdr の別 pane を開いて Claude Code を起動する

**却下の理由。**返答のたびに定額のレートリミットを使う別セッションを1つ立てることになる。

### 4-7. 記録する発言を AI が選別する

**却下の理由。**選別した瞬間に AI の判断が入り、いまと同じ穴が開く。

## 5. いま動いているもの / 動いていないもの

**言いたいこと。****道具は3本書けてテストも付いたが、どの hook にも登録しておらず、
1度も走らない。**そのため、**このリポジトリのどの branch にも置いていない。**
**取り出し方は下にある。**登録する前に、走らせる中身の安全は先に決めてある。

### 5-1. 書けているもの（このリポジトリには置いていない）

| ファイル | 何をするか |
| --- | --- |
| `.claude/hooks/task_common.py`（426行） | 記録の読み書き・確かめ方の判定・**確かめ方の形の検査**（`verify_rejection`） |
| `.claude/hooks/task-store.py`（297行） | 記録の読み書き（`add` / `close` / `merge` / `list`） |
| `.claude/hooks/check-open-tasks.py`（148行） | `Stop` で走り、確かめ方が通っているのに閉じていないものがあれば `{"decision": "block"}` を出す |
| `.claude/hooks/tests/test_task_store.py`（522行） | 上の2本のテスト |
| `.claude/hooks/tests/test_check_open_tasks.py`（158行） | `check-open-tasks.py` のテスト |

**なぜ置いていないか。****どの hook にも登録しておらず、1度も走らないためである。**
動かないものを置くと、次に読む人が「これは動いている」と読む
（[.claude/rules/reporting.md](../../.claude/rules/reporting.md) の「事実の扱い」）。

**取り出し方。**5本とも commit `ea8090db145f1001c7f89cc054b34ca906d2fe91` に入っている。

```bash
git show ea8090db145f1001c7f89cc054b34ca906d2fe91:.claude/hooks/task_common.py
```

**記録そのものも git に入れない設計である。**置き場所は `.claude/requests/` で、
**人間の発言の原文がそのまま入る。**このリポジトリは PUBLIC なので、
**登録するときに `.gitignore` へ足すこと。**

**`check-open-tasks.py` は未完了そのものでは止めない。**まだ着手していない指示が並んでいるだけのことがあるため。

### 5-2. `verify` は、通してよい形しか走らせない

**`verify` は LLM が書いた文字列で、`Stop` のたびに shell へ渡る。**
確認も承認も挟まらないので、`task_common.py` の
`verify_rejection` が**通してよい形だけを通す。**

| どこで見るか | 通らなかったらどうなるか |
| --- | --- |
| **`task-store.py add`**（登録するとき） | **記録に書かずに終了コード 1。**断った理由と、書き直し方の例を出す |
| **`task_common.run_verify`**（走らせるとき） | **走らせない。**「実行していません」と断った理由を、そのまま AI と人間へ見せる |

**通すもの。**`grep` / `rg` / `test` / `echo` / `cat` / `wc` / `ls` / `jq` などの読むだけのコマンドと、
`git` の読み取り（`log` / `show` / `diff` / `grep` など）、`gh` の読み取り（`pr view` / `release list` /
GET だけの `api` など）、`continuo version`。これらを `&&` `||` `|` `;` で繋いだもの。

**通さないもの。**リダイレクト（`>` `<`）・バックグラウンド（`&`）・`$(…)` と backtick・
`sh` / `python3` / `curl` のような何でも走らせられるもの・`git commit` や `gh pr comment` のような書き込み。

### 5-3. できていないもの

| 何 | 状態 |
| --- | --- |
| **`UserPromptSubmit` hook の登録**（`type: "agent"` か `"prompt"`） | **未実施** |
| **`Stop` hook への `check-open-tasks.py` の登録** | **未実施** |

**実測**（2026-09-02、[.claude/settings.json](../../.claude/settings.json)）。
`Stop` 2本（`check-verified-commands.py` / `check-reply-clarity.py`）と
`PreToolUse` 1本（`block-merge-without-review.py`）のみ。
