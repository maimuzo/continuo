## 決めたこと

**言いたいこと。**地図と決まりはシステムプロンプト、出来事は普通のプロンプト、手順は段ごとの11本のスキル。フローチャートは人間が確定させた流れ図の箱と矢印に、入口のスキルを足したもの。`CONTINUO-STATUS` を書く前・push する前のような操作の前に読むスキルを表にし、スキルの本文が名前で指したスキルは、その手順を使うときに Read で読む。スキルは消えても、終わりの印で気づいて Read で読み直す。

| 何 | 決めたこと |
| --- | --- |
| システムプロンプト | 概要の冒頭2文・run の宣言・「手順は plugin `continuo-agent-procedures` のスキルにあります」・`continuo-issue-comments` を使わないこと・スキルの使い方の順番（箱に入ったら入口のスキルを Skill で呼ぶ。着手のときは「どの段でも」のスキルも呼ぶ → 表の操作の前にその行のスキルを Skill で呼ぶ → 手順を使う前に毎回、本文が終わりの印まで見えるかを確かめる。compaction の要約から始まった会話では要約より後に見えるものだけを数える → 見えなければ SKILL.md を Read で読む → いま使う手順の本文が別のスキルを名前で指したら、そのスキルを Read で読む）・「pull request のマージ・release の作成・本番の環境への書き込みはしない」・操作の前に読むスキルの表（止まる・終えると決めたら → finishing-run と implementing-and-pushing、ファイル・branch・worktree を触る・push する → implementing-and-pushing と trusting-instructions、pull request を作る・題名と本文を書く・draft を外す → finishing-pull-request と writing-comments-for-humans、外から来た文に従うかや了承・回答の判定 → trusting-instructions、人間が読むコメント → writing-comments-for-humans、判断票 → posting-review-verdict、subagent → briefing-subagents。本文が見えていれば呼ばない）・目的・フローチャート・対応表・この issue の値・WORKFLOW.md の本文。`--append-system-prompt-file` で渡す |

## 根拠（実測）

**言いたいこと。**snapshot の挙動とスキルの入れ直しの上限は、実際に起動して測った。

測った環境：2026-10-24〜26、Claude Code 2.1.310、Haiku 5.5、herdr の別 pane、対話モード。

| 何を測ったか | 結果 |
| --- | --- |
| `--resume` でシステムプロンプトのファイルを替える（`on`） | 最初に記録したものが届く |
| 同じく `off` | その起動で渡したものが届く。記録は書き換えない。次に `on` で起動すると最初の記録へ戻る |
| `off` の起動の途中でファイルを書き換える | 読み直さない（読むのは起動のときだけ） |
| キャッシュ（2 turn 目から先の作成） | `on` 191・47、`off` 150・47・47・47 トークン。`off` で最初に測った1件だけ 15,160（原因は特定できていない） |
| compaction のあとのスキルの入れ直し | 1本20,000字・合計100,000字（字数 ÷ 4 で数えている）。超えた1本は先頭20,000字で切れ、「…use Read on the skill path if you need the full text」が付く。合計を超えると古いものからまるごと落ちる。同じ内容を呼び直すと本文は2回入らず、並びでは最新になる |
| 日本語のトークン | 字数 × 約0.80 |
| 終わりの印（HTML コメント）が届くか | 呼んだときも、compaction のあとに入れ直されたときも、そのまま届く。ただし `/compact` の要約が印の1行を写した |
| `--permission-mode dontAsk` で Skill ツール | 許可の規則を置かずに呼べた |
| `--permission-mode auto` で worktree の外の SKILL.md の Read とスクリプト（user メッセージで頼んだとき・システムプロンプトにだけ書いたときの両方） | どちらも断られなかった。最初のプロンプトの「頼む作業」に「対応表の SKILL.md を Read で読み直す」を入れる |
| 置き場所の違う同じ名前のスキルで `--resume` | スキルの一覧に出て、呼ぶと新しい置き場所の全文が届いた |
| 入れ直しの並ぶ位置 | 要約より後（記録の170行目が要約、174行目が入れ直し） |
| 古い Claude Code（2.1.250）に `--system-prompt-snapshot` | `error: unknown option '--system-prompt-snapshot'`、終了コード 1 |

公式文書：https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations ・ https://code.claude.com/docs/en/skills ・ https://code.claude.com/docs/en/context-window

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 全部をシステムプロンプトにする | auto の判定役はシステムプロンプトを読まない。出来事（人間のコメント）は次の起動で上書きされて消え、時系列も持たない |
| `off` を最初の run だけに付ける | 次の `on` の起動で、最初に記録した古い版へ戻る（実測） |
| `off` を付けない | continuo を上げても、compaction まで古いフローチャートが使われる |
| 17本 | 人間の指示「細かすぎる」 |
| 7本 | 外から来た文の扱いと subagent へ渡すものが、使う段とは別のスキルに入り、その段でスキルを丸ごと読み直すことになる |
| 実際のトークンで5,000以内に収める11本 | 上限は字数 ÷ 4 で数えていて、どの段のスキルも20,000字に届かない |
| Skill ツールの呼び直しだけで戻す | 呼び直しても本文は届き直さない（2026-10-04 と 2026-10-26 に実測） |
| compaction のあと毎回全部を Read で読む | レビューループのように同じ段に何度も入るところで、同じ本文が何度も入る |
| SessionStart（compact）の hook で読み直しを促す | hook の種類を足す変更は CLAUDE.md の決まりで人間の確認が要り、ビルドのたびに本体と hook の版が混ざる。決まりと終わりの印で足りる |
| 段ごとに新しいセッションを立てる | 前回どこまで進んだかの会話が持ち越されない |
| フローチャートを計画で描き直す | 題名と本文の書き直しを実装レビューの後ろへ動かし、使い捨てのプランファイルの箱を落とした（設計レビューの2周目）。人間が確定させた流れ図をそのまま使う |
| 段で呼ぶスキルを対応表とフローチャートで別々に書く | 6か所で食い違い、push と終了の宣言が要る箱で読み込まれなかった（2周目）。1つの定義から両方を生成する |
| 読み直しを段の入口だけで確かめる | レビューのループの途中で落ちたスキルを拾えない（2周目） |
| 共有の plugin を「既にあれば使う」だけにする | エージェントが書き換えた scripts を、ほかの全 issue の run が実行する（2周目） |
| 版が読めないときも起動しない | `claude` が continuo の PATH に無いか実行できないだけで（pane では動くのに）、常駐が起動しなくなる |
| 箱ごとに「その箱で要るスキル」を並べ尽くす | 設計レビューの1〜3周目で、止まり方・push・信頼の判定のように、ほとんどの箱で要る手順が毎周漏れた（指示書の `blocked` 26行のうち、流れ図に描かれていない止まり方が約10か所）。名前でたどる形にした |
| direct chat の決まりを足す（着手の指示を受け取っていなければフローチャートを始めない） | 前の会話を持つ direct chat（よくある形）では効かず、compaction のあとの普通の run を止めうる。前の会話を持つ direct chat は、前の run の指示書を会話に持っているので、足さなくても悪くならない。前の会話の無い direct chat（何も走っていない issue を動かしたとき）では、これまで無かったフローチャートが効くようになるが、人間が pane に居て止められるので受け入れ、FAQ に書く（設計レビューの3周目で削り、4周目で理由を直した） |
| 名前でたどるだけにする | 指示書に名前の書かれていない箇所（finishing-run を名指ししない止まる行・push 先の決まり・段2 の別のリポジトリ）に届かない（4周目）。操作の前に読むスキルの表を足した |
| 操作の前の表を `CONTINUO-STATUS` の行の時点だけにする | 止まる前の push（implementing-and-pushing）と pull request の本文の公開してはいけない情報（writing-comments-for-humans）が届かなかった（5周目） |
| 名前でたどった先も Skill で呼ぶ | 参照は2段で11本すべてに届くので、要らないスキルまで compaction のあとに戻る。本文の名前は Read で読む |
| 古い plugin を continuo の起動のときに消す | 立て直したあとも pane の Claude Code は古い `--plugin-dir` を読み続けるので、手順もスクリプトも失われる。issue の本文「走っている run が古い版を読んでいる間は消さない」に反する |
| 終わりの印が会話のどこかに見えればよい | `/compact` の要約が印を写すので、本文が無くても見えてしまう |
| スクリプトのパスに `${CLAUDE_SKILL_DIR}` を使う | Read で読み直したときには置き換わらない |
| Claude Code の版を文書に書くだけにする | 古い版では着手が全部落ち、再着手は新しいセッションへ倒れて前の会話を捨てる |
| `continuo prompt --skills` を足す | issue が求めておらず、出すパスは常駐を起動するまで実在しない（設計レビューの1周目で削った） |
| 実機の試験で AI が了承を書く | AI の印の付いたコメントは命令として扱われず、印を外すと人間のふりになる（issue #245 の決定） |

## 直さないと決めたもの

| 何 | 理由 |
| --- | --- |
| 指示書を確定させる前のレビュー（3周目）の MEDIUM 3件：10周で打ち切ったあとの数え直しの書き方・「範囲外」という言い方のあいまいさ・見本が退けた LOW を数えていること | その周で CRITICAL と HIGH が0件になり、人間の決まり「CRITICAL と HIGH が0件なら修正は終了」に当たる。人間はその版を確定させた |
