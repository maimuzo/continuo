# レートリミットのマージンと、走っている run の扱い

**言いたいこと。**マージンは「人間のために残しておく割合」である。**マージンが1以上の期間で余裕%が0以下になったら、continuo が起動したエージェントはそれ以上作業しない。**着手の前でも、走っている最中でも同じである。

**この文書は、issue #273（エージェントが黙っても枠の状態が画面にもログにも出ず、60分後に「固まった」とだけ報告される）のコメントで人間が決めた考え方を抜き出したものである**（2026-10-05 から 2026-10-17）。issue #262（レートリミットに余裕があって始めたタスクでも途中で余裕がなくなった時に停止したい）と一緒に直した。レートリミットに関わる作業は、ここを共有の仕様として使う。設計の判断の記録は [docs/plans/continuo_design.md](../plans/continuo_design.md) の 3-27a にある。

**2つの節に分けている。**「人間が決めた考え方」は人間の原文の引用で、AI は書き換えない。「人間の決定から AI が導いた決まり」は、原文を実装に落とすときに AI が決めたもので、設計レビューを通している。**食い違ったら、人間の原文が勝つ。**

## 単語

| 語 | 意味 |
| --- | --- |
| マージン | 人間のために残しておく割合（%）。5時間の期間は `tracker.provider.handoff.five_hour_margin_percent`、1週間の期間（全体の `weekly_all` とモデル別の `weekly_scoped`）は `weekly_margin_percent`。既定はどちらも10 |
| 余裕% | `100 − (使用済み% + マージン%)`。期間ごとに別々に計算する。コードでは「余裕値」と呼ぶ |
| マージンを切る | **マージンが1以上の期間で**、余裕%が0以下になること（使用率100も含む）。マージンが0の期間は、使用率100に達しても「マージンを切る」とは呼ばない |
| Claude Code が動けない | 5時間の期間か、全体の1週間の期間（`weekly_all`）が使用率100であること。モデル別の1週間の期間（`weekly_scoped`）の100は数えない |
| 上限（待つ上限） | `rate_limit.weekly_wait_limit_minutes`（既定300分）。1週間の期間のリセットまでの残りと比べる。0 は「上限なし」 |
| 切り上げる | エージェントが作業を中断し、commit・push・引き継ぎのコメントを済ませて turn を終えること |
| 手放す（担当を外す） | continuo が自分の担当者を外し、`released` のコメントを書くこと。Status は動かさない。余裕のある別の機械が入札して続きを拾える |

### マージンを0にするかで挙動を変える（2026-10-05 12:32）

> - 5時間レートリミットは、着手時点でレートリミットにマージンがなければ立候補しないので担当者にならない。
>   - ただし、自分が担当になった後の挙動がどうなっているかは確認必要。担当になっているが一度blockedなどになっている状態で、レートリミットはマージンを切れているケースで、今どういう実装になっているかまとめて。
>   - 本来なら5時間レートリミット用マージンが0%になっているかどうかをみて、0%ならレートリミットまで使い切って、使い切ったらそのままレートリミットがリセットされるまで待ち続ければいい。0%以上なら動作中にレートリミットを定期的に確認し、マージンに足りない時は新たにissueに着手せずに理由を書いてblockedに戻すか、途中でも良いから一旦pushして途中までであることをコメントに書いてblockedに戻すべき。

## 人間の決定から AI が導いた決まり

**ここから下は、上の原文を実装に落とすときに AI が決めたことである。**根拠と、比べて退けた案は設計 3-27a にある。

### 判定の式

```text
マージンを切った期間:
    マージンが1以上の期間で、余裕% <= 0 のもの（使用率100も含む）
    モデル別の1週間の期間の100%も、1週間のマージンが1以上なら入る
Claude Code が動けない:
    5時間の期間か、全体の1週間の期間が使用率100（モデル別の1週間の期間は数えない）
走っている run で切り上げさせる:
    マージンを切った期間が在り、かつ、Claude Code が動けない、ではない
着手の前（担当が自分の issue）に止める:
    マージンを切った期間が在るか、Claude Code が動けない
```

- **マージンが0の期間は「マージンを切る」に入れない。**原文の「0%ならレートリミットまで使い切って」のとおりである。マージン0の期間の使用率100は、走っている run では今の動き（待つか手放す）、着手の前では「Claude Code が動けない」に当たる。
- **モデル別の1週間の期間の100%を「動けない」に入れない。**continuo は Claude Code がどのモデルを使っているかを知らないので、使っていないモデルの期間が100%でも Claude Code は動けることがある。
- **入札は今のまま。**入札は「余裕%が0以下の期間がある」（マージン0の期間の使用率100を含む）で止める。

### 行き先の表

マージンを切った期間（着手の前は、Claude Code が動けない期間も）の種類で行を選ぶ。**5時間の期間と1週間の期間が両方当たるときは、1週間の期間の行を使う**（担当を外すが出うるのは1週間の期間だけ）。1週間の期間は、全体とモデル別を分けずに1つの判定で決め、上から当てる。

| 期間 | 条件 | 走っている run（turn の終わり） | 着手の前（run が無い） |
| --- | --- | --- | --- |
| 5時間の期間だけ | — | `Blocked` へ戻す（Status を `failure_state` へ。担当者は残す） | `Blocked` へ戻す |
| 1週間の期間 | 待つ上限が0 | `Blocked` へ戻す | `Blocked` へ戻す |
| 1週間の期間 | 読めている期間のどれかで、リセットまでが上限を超える | 「行き先を待つ」印を立てる（担当を外すのは巡回の手放し） | 担当を外す |
| 1週間の期間 | どれか1つでもリセットの時刻を読めない | 「行き先を待つ」印を立てる | `Blocked` へ戻す |
| 1週間の期間 | リセットまでが上限以内 | `Blocked` へ戻す | `Blocked` へ戻す |

- **上限以内を `Blocked` にするのは、原文の質問2への答え「ここは5時間レートリミットと同じロジックで良い」と、その読み「切り上げて Blocked へ戻し、担当者は残す」への「この理解で良い」による。**原文の「そのまま待つ」は、この読みで `Blocked` に揃えた。
- **上限を超えると分かっている期間があれば、読めない期間があっても「超える」の行を使う。**「blockedに戻すで良い」は、読めないときだけを訊いた答えである。
- **`Blocked` へ戻すときは、理由のコメントに、切った期間とリセットの時刻（読めないときは「不明」）を書く。**人間はそれを見て、いつ `Ready` へ戻すかを決める。
- **担当を外す前には、Claude Code が動けるなら、必ず push と引き継ぎのコメントを書かせる。**走っている run では切り上げの turn が、着手の前ではいつもどおり始めた run の最初の turn がそれに当たる。**Claude Code が動けないなら、何も走らせずに外す**（理由の値 `weekly_wait_limit_not_started`）。
- **着手の前に `Blocked` へ戻すときは、Claude Code を起動しない。**issue を ID で取り直し、Status と担当者がそのままのときだけ Status を書く。

### Claude Code が動けないとき

- **走っている run は、マージンの値によらず、切り上げのあとでも、今の動き（リセットを待つ。1週間の期間で上限を超えるなら手放す）である。**切り上げの指示も送らない（応答できない）。原文の「リセットを待つで良い」のとおりである。
- **着手の前は、この限りではない。**行き先の表に当てる。

### 使える値

- **判定に使う値は「使える値」である。**最後に使用率を読めた時刻から30分以内なら、保管値のうち、リセットの時刻を過ぎていない期間と、リセットの時刻を読めない期間を使う。
- **使える値が1つも無いあいだは「使用率を読めていない」として、着手の前でも走っている run でも止めない**（`rate_limit.source: none`・立て直してからまだ読めていない・最後に読めてから30分を過ぎた）。
- **担当を外す判定だけは、新しい値（入札と同じ新しさ）でしか行わない。**担当を外すと戻せないためである。着手の前に「担当を外す」に当たっても、新しい値で同じ答えにならなければ、その巡回では着手も手放しもせず `Ready` のまま残す。

### 誰が何をするか

**切り上げは、continuo が外から割り込んで行うものではない。エージェントが自分で行う**（原文の「メインエージェントが自ら制御する話だ」）。

| 誰が | 何をするか |
| --- | --- |
| **continuo** | 巡回のたびに、判定の結果を1行のファイル `margin-status` に書く。**働いている最中には割り込まない。**turn が終わったところで判定し、切っていたら「続けてください」の代わりに切り上げの指示を1回送り、その次の turn の終わりに上の表の行き先へ流す。最初の turn で切っていたら、指示書の後ろに「作業は始めずに、5-8 の切り上げだけを行ってください」を添える。着手の前にも判定する |
| **エージェント** | 組み込みの指示書の 5-8 に従い、区切りごと（時刻を確かめるとき・サブエージェントを起動する前・長いコマンドを叩く前）に `cat '<margin-status>'; date +%s` を叩く。`MARGIN: cut` で `expires_at` が未来なら切り上げ、表明は `working` で終える。continuo から切り上げの指示が届いたときも同じ（済んでいれば何もせずに終える） |

**エージェントの切り上げ方**（組み込みの指示書の 5-8）。

1. 新しいサブエージェントは起動しない。走っているサブエージェントは止めない
2. 先に、いまある変更を commit して push する
3. 走っているサブエージェントの結果が返ったら、その分も commit して push する
4. どこまで進んだか・次に何をするかを、issue のコメントに書く
5. 応答の最後に `CONTINUO-STATUS: working` を書いて終える。そのあと人間へ戻すか、別の機械へ引き継ぐかは continuo が決める

**行き先を決めるのは continuo である。**エージェントは「いつ譲るか」だけを決める。エージェントの判定と continuo の判定は、同じ判定の結果（`margin-status`）を土台にする。

### `margin-status` の形

```text
MARGIN: cut kind=session used=93 margin=10 resets_at=2026-10-07T14:00:00+09:00 expires_at=1791336000
```

| 欄 | 意味 |
| --- | --- |
| `cut` / `ok` / `unknown` | マージンを切った期間が在る / 無い / 使える値が1つも無い |
| `kind`・`used`・`margin`・`resets_at` | 切った期間ごとに並べる。`resets_at` は機械のタイムゾーンの RFC3339。読めない期間は `unknown` |
| `expires_at` | この1行を信じてよい期限（UNIX 時刻の秒）。書いた時刻に「巡回の間隔の3倍」と「10分」の長いほうを足す。ただし切った期間のいちばん早いリセットより後にしない |

- **置き場所は、hook を受ける socket と同じディレクトリ（実行時ディレクトリ）の `margin-status`。**`rate_limit.source: none` の機械では書かず、組み込みの指示書の 5-8 も出さない。
- **usage API とステータスラインのどちらから届いた使用率にも効く。**continuo 本体が、どちらの値も同じ保管値に入れているためである。

### 「行き先を待つ」印

- **走っている run で、1週間の期間で担当を外しうるとき（上の表の2行）に立てる。**立てたら、continuo は何も送らずに turn ループを抜ける。
- **巡回が、使える値で行き先を決め直す。**マージンを切った期間がもう無ければ（リセットされた）、または使える値が無くなったら、印を下ろして作業へ戻す。行き先が `Blocked` に変われば `Blocked` へ戻す。そうでなければ、担当を外すかを巡回の手放し（設計 3-27）に任せる。
- **Claude Code の状態を読めて止まっている限り、60分の打ち切りの対象から外す。**
- **direct chat に入れたとき・戻したとき・新しい試行を始めるときに下ろす。**direct chat のあいだは何もしない。
- **ダッシュボードの run の欄に `waiting_handoff` として出す。**

### 残る限界

- **1つの turn が長いと、エージェントが確かめるまで止まらない**（turn の終わりでは止まる）。
- **切り上げにも使用率を使う。**そこで使用率100%に達すると、今の使用率100%の待ちに入る。
- **continuo を起動し直すと、切り上げ済みの記録と「行き先を待つ」印が消える。**pane が残っていれば、切り上げの指示がもう1回届く。
- **direct chat のあいだも、エージェントは 5-8 に従って切り上げうる。**人間が「マージンは気にせず続けて」と書けば続く。
- ほかの限界は設計 3-27a の「残る限界」にある。
