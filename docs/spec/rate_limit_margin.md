# レートリミットのマージンと、走っている run の扱い

**言いたいこと。**マージンは「人間のために残しておく割合」である。**余裕%が0以下になったら、continuo が起動したエージェントはそれ以上作業しない。**着手の前でも、走っている最中でも同じである。

**この文書は、issue #273（エージェントが黙っても枠の状態が画面にもログにも出ず、60分後に「固まった」とだけ報告される）のコメントで人間が決めた考え方を抜き出したものである**（2026-10-05 から 2026-10-06）。レートリミットに関わる作業は、ここを共有の仕様として使う。設計の判断の記録は [docs/plans/continuo_design.md](../plans/continuo_design.md) の 3-27 にある。

## 単語

| 語 | 意味 |
| --- | --- |
| マージン | 人間のために残しておく割合（%）。5時間の期間は `tracker.provider.handoff.five_hour_margin_percent`、1週間の期間は `weekly_margin_percent`。既定はどちらも10 |
| 余裕% | `100 − (使用済み% + マージン%)`。5時間の期間と1週間の期間で、別々に計算する。コードでは「余裕値」と呼ぶ |
| マージンを切る | 余裕%が0以下になること |
| 上限 | `rate_limit.weekly_wait_limit_minutes`（既定300分）。1週間の期間のリセットまでの残りと比べる |
| 切り上げる | エージェントが作業を中断し、commit・push・引き継ぎのコメントを済ませて turn を終えること |
| 手放す | continuo が自分の担当者を外し、`released` のコメントを書くこと。Status は動かさない。余裕のある別の機械が入札して続きを拾える |

## 余裕%

- 余裕%が0以下の期間が1つでもあれば、それ以上は作業しない
- **マージンが0の期間は、レートリミットに当たるまで使い切ってよい。**余裕%が0以下になるのは使用率100のときだけなので、切り上げは起きない
- **判定は1つである。**「余裕%が0以下で、使用率が100未満の期間がある」。マージン0のための分岐は持たない
- 使用率を読めていないあいだ（`rate_limit.source: none` を含む）は、この仕様で run を止めない

## 着手

| 誰の issue か | 余裕%が0以下のとき |
| --- | --- |
| 担当者のいない issue | 入札しない（担当者にならない） |
| 担当が自分にある issue（一度 `Blocked` へ落ちたものなど） | run を始めない。行き先は下の表と同じにする。**Claude Code は起動しない** |

## 走っている run

| 期間 | マージン | いつ | 何が起きるか |
| --- | --- | --- | --- |
| 5時間 | 0 | 使用率100 | セッションを保ったまま、リセットを待つ。リセットされたら再開する |
| 5時間 | 1以上 | 余裕%が0以下 | 切り上げて、Status を `failure_state`（既定 `Blocked`）へ戻す。担当者は残す |
| 1週間 | 0 | 使用率100 | リセットまでが上限以内なら待つ。上限を超えるなら手放す |
| 1週間 | 1以上 | 余裕%が0以下で、リセットまでが上限を超える | 切り上げて、手放す |
| 1週間 | 1以上 | 余裕%が0以下で、リセットまでが上限以内 | 切り上げて、Status を `failure_state` へ戻す。担当者は残す |

- 2つの期間が同時に当たったときは、手放す行を優先する
- **手放すのは、新しい使用率を読めているときだけである。**読めていなければ `failure_state` へ戻す
- 上限を設けていない機械（`weekly_wait_limit_minutes: 0`）と、リセットの時刻を読めない期間は、上限以内として扱う

## 誰が何をするか

**切り上げは、continuo が外から割り込んで行うものではない。エージェントが自分で行う。**

| 誰が | 何をするか |
| --- | --- |
| **エージェント** | 区切りごとに `continuo margin` を叩いて、マージンを切っていないかを確かめる。切っていたら切り上げ、表明は `working` で終える |
| **continuo** | turn が終わるたびに同じ判定を行い、切っていたら次の指示を送らずに、上の表の行き先へ流す。着手の前にも同じ判定を行う |

**エージェントの切り上げ方。**

- **走っているサブエージェントは止めない。**結果が返るまで待ってよい
- **新しいサブエージェントは起動しない**
- メインのエージェントは作業を中断し、commit・push・引き継ぎのコメントを書くことに専念する。終わったら turn を終える
- **push と引き継ぎのコメントは、レートリミットに達していない限り、最優先で行う**

**行き先を決めるのは continuo である。**エージェントは「いつ譲るか」だけを決める。エージェントの判定と continuo の判定は、同じ使用率と同じ式を使う。
