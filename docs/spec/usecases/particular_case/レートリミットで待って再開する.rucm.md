# ユースケース: レートリミットで待って再開する

> **レートリミットの扱いのうち、turn の待ち（`afterWaitTimeout` → `afterQuotaReset` → `turnLoop`）が行う側だけを書いた記述である。**
> 巡回が行う側（枠待ちの run の打ち切りを止める・1週間の枠を待つ上限で担当を手放す）は `枠待ちの run の打ち切りを止める` に在る。
> 2つは別の goroutine が独立に行うので、1本に並べると経路が掛け算で増える。分けて書く（人間の決定。2026-10-02）。
>
> **継続の指示を送るのは、この記述の側だけである。**巡回は送らない。
> **`failure_state` へ落として人間へ渡す処理（`finishRun`）と、pane を閉じてリトライを積む処理（`abandonRun`）は、
> `issue を1件処理する` と同じ実装を通る。**この記述には、枠待ちから出る入口と、終わったときの状態だけを書く。

## この記述で使う言葉

| 語 | 何を指すか |
| --- | --- |
| **turn の待ち受け** | `agent.prompt` に付けた待ち（`until` = `claude.wait_until`、`timeout_ms` = `claude.turn_timeout_ms`）。時間切れは herdr が `timeout` の誤りとして応答する |
| **run が枠待ちである** | 次の2つが同時に成り立つこと（`isQuotaWaiting`）。**(1)** 保管している期限内の枠に使用率が 100 の枠がある。**(2)** その run がこの turn で hook を1件も受けていないか、最後に動いていた時刻から `claude.turn_timeout_ms` が過ぎている |
| **枠待ちの印** | run が持つ `WaitingQuota`。立っているあいだ、巡回はその run の打ち切りの判定を飛ばす（`枠待ちの run の打ち切りを止める`） |
| **印** | 走行中の run の登録（`o.runs`）。**枠待ちの印とは別物である** |
| **枠が明ける** | 「使用率が 100 の枠のリセット時刻を過ぎた」か「保管している期限内の枠に使用率が 100 の枠が無くなった」のどちらかが成り立つこと |
| **継続の指示** | turn ループが2回目以降に送る本文（`BuildContinuationPrompt`） |

## 段にしていない分岐

**終わり方も、そのあと通る段も変わらない分岐は、段にせずここへ置く。**

| どこで | 何が起きるか | どうなるか |
| --- | --- | --- |
| 段1 | 入口がもう1つある。`Stop` を待ち直している最中（`confirmTurnEnd`）に、`claude.poll_wait_ms` のあいだ `Stop` が来なかったとき | 同じ `isQuotaWaiting` を見て、真なら段3 から通る。偽なら `blocked` を見てから待ち続ける |
| 段2 | 2つの条件のどちらが欠けても | `枠待ちではない待ち受け` へ進む。**ここでは打ち切らない。**打ち切るかどうかは巡回だけが決める |
| 段3 | 巡回が先に同じ印を立てている（`枠待ちの run の打ち切りを止める` の段6） | 立て直すだけで、結果は同じである |
| 段5 | herdr が待ちの時間切れを応答する（`claude.poll_wait_ms`） | 失敗として扱わず、段6 へ進む |
| 段5 | herdr が idle か done を応答したが、`Stop` hook を受けていない | 何もせず段6 へ進む。**`agent.wait` はいまの状態が `until` に含まれると即座に返る**ので、1周あたり `claude.poll_wait_ms` は必ず空ける |
| 段5 | continuo 自身が worker を止めていた（`selfStoppedTurn`）、または停止を求められている | 何も書かずに turn の待ちを抜ける。別の経路がその run を終わらせている最中である |
| 段9 | herdr が `agent.get` に誤りを返す | WARN を1行出して、送る側へ進む（段10 の真の側） |
| 段9 | agent_status が idle・done・unknown である | 送る側へ進む（段10 の真の側） |
| 段11 と段12 のあいだ | 継続の指示ではなく1回目の本文を送る run（まだ1回目を送り始めていない run）で、本文の組み立てに失敗する | `failure_state` へ落とす（`failRun`）。`issue を1件処理する` の `本文の組み立ての失敗` が受け持つ |
| `確認の画面` の段3 より前 | 走っている subagent が終わるのを `claude.poll_wait_ms` まで待つ | `issue を1件処理する` の `権限の確認` が受け持つ |
| `待ち直しの失敗` の「pane を閉じる」 | herdr が pane を閉じ損ねる | **閉じた記録を書かない。**保留も捨てる（`settleClosedRecord`）。あとの段はそのまま続く |
| `指示の回数の上限`・`確認の画面` の INCLUDE の中、印を外す前 | 取り直した Status が `cleanup.on_states` に入っている | worktree と branch を片付ける（`finishRunClaimed`）。**前提で外した**（`failure_state` は `cleanup.on_states` に入っていない） |
| `指示の回数の上限`・`確認の画面`・`リトライの使い切り` の INCLUDE | 成果の報告が無く、書かせ直しにも失敗する | `run を終えて worker を止める` の代替フローが受け持つ。Status は既に `failure_state` で、通知も投稿済みなので、どちらも重ねて書かれない |

## 巡回だけが印を外す場合

**turn の待ちが `待ち直しの一時的な失敗` で畳まれているあいだに枠が明けると、印を外すのは巡回だけになる**
（`枠待ちの run の打ち切りを止める` の段10）。**そのとき継続の指示は送られない。**

| 順 | 誰が | 何をするか |
| --- | --- | --- |
| 1 | turn の待ち | herdr へ届かず、印を残したまま turn ループを畳む（`turnTransient`） |
| 2 | 次の巡回 | turn ループを「turn を送らずに待つ」形で立て直す（`wakeRuns`） |
| 3 | 立て直した turn ループ | `Stop` を `claude.poll_wait_ms`（既定30秒）のあいだ待ち切ってから、枠待ちかを見る（`confirmTurnEnd`） |
| 4 | 立て直した turn ループ | 枠待ちなら、この記述の段3 から通り直す |

**窓は「畳まれてから、次の巡回 + `claude.poll_wait_ms`」までである。**この窓の中で枠が明けると、順3 の時点で枠待ちではないので、
turn ループは `Stop` を待ち続ける。印を外した時刻から `claude.turn_timeout_ms` のあいだ進んだ形跡が無ければ、
巡回がその run を打ち切ってリトライを積む（`枠待ちの run の打ち切りを止める` の `枠の残り`）。バックオフが明けた再 dispatch が続きを受け持つ。

**継続の指示を送ったあとに応答が無い run にも、専用の分岐は無い。**次の待ち受けの時間切れで、この記述を段1 からもう一度通る。

## 枠明けに継続の指示を送ってよいか

**Claude Code 2.1.234 は枠のリセット時にセッションを自動で継続する**（設計 3-27）。
段9 で読んだ `agent_status` で分かれる（`internal/orchestrator/turn.go` の `afterQuotaReset`）。

| agent_status | どうするか | この記述のどこか |
| --- | --- | --- |
| idle または done | 送る。Claude Code は継続していない | 基本フロー |
| unknown | 送る | 基本フロー |
| 読めなかった（herdr が誤りを返した） | 送る。WARN を1行出す | 基本フロー |
| working | 送らない。Claude Code が自分で継続している。turn の終わりを待つ | `自動継続` |
| blocked | 送らない。esc を送ってから failure_state へ落とす | `確認の画面` |

**`確認の画面` の細部（走っている subagent を待つ・引き渡しの通知の文面）は、`issue を1件処理する` が受け持つ。**
この記述には、枠待ちから出る入口と、終わったときの状態だけを書いた。

## シーケンス図

```mermaid
sequenceDiagram
    participant H as herdr
    participant S as システム
    participant CC as Claude Code
    participant GH as GitHub

    H-->>S: turn の待ち受けの時間切れを応答する
    alt run が枠待ちではない
        Note over S: ABORT turn を送り直さずに、turn の終わりを待ち直す
    else run が枠待ちである
        S->>S: 枠待ちの印を立てる
        loop 枠が明けるまで
            S->>H: agent が待機状態になるまでの待ちを要求する
            alt herdr が blocked を応答する
                S->>CC: esc を送る
                S->>GH: Status への failure_state の書き込みを要求する
                Note over S: ABORT 確認の画面。人間へ渡す
            else herdr が idle か done を応答し、Stop hook を受けている
                Note over S: ABORT 印を外して turn の終わりの処理を始める
            else 待ちの要求が一時的な理由で失敗する
                Note over S: RESUME STEP 2 印を残す。次の巡回で turn の待ちを立て直す
            else 待ちの要求が一時的ではない理由で失敗する
                S->>H: pane の close を要求する
                Note over S: ABORT 印を外してリトライを1つ積む。使い切っていれば failure_state へ落とす
            end
        end
        S->>S: 枠待ちの印を外す
        S->>S: 最後に動いていた時刻を進める
        S->>H: agent_status を要求する
        H-->>S: agent_status を応答する
        alt agent_status が blocked である
            Note over S: ABORT 確認の画面。継続の指示を送らない
        else agent_status が working である
            Note over S: ABORT 継続の指示を送らない。Claude Code が自分で継続している
        else turn 数が max_dispatch_turns に達している
            S->>GH: Status への failure_state の書き込みを要求する
            Note over S: ABORT 継続の指示を送らない。人間へ渡す
        else それ以外
            S->>S: turn 数を1つ増やす
            S->>CC: 継続の指示を送る
        end
    end
```
