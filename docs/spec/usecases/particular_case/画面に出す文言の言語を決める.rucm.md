# ユースケース: 画面に出す文言の言語を決める

## 根拠資料

- `docs/plans/continuo_design.md` の「3-35. 画面に出す文言は資源から引く」（言語の決め方・設定を主とし環境変数を従とすること・どれでも決まらないときを英語にする理由・読む環境変数を増やさない理由）

## いつ走るか

**利用者がどのサブコマンドを打っても、起動の直後に必ず1回走る。**
`internal/cli/cli.go` の `RunWith` が、引数を振り分けるより前に環境変数から言語を決める。
**引数の誤りを報告する文言も、この決定のあとに出る。**

**設定ファイルを読むコマンドは、そのあとでもう一度決め直す。**
**設定が主で、環境変数が従である。**

**ネットワークインストーラー（`install.sh`）は、この決め方の外である。**言語を決める処理を持たず、文言は日本語に固定である（英語は、release がまだ1つも無いときの画面の1行だけ）。

**資源の検査は、それより前に走る。**`internal/i18n/i18n.go` の `init` は package の初期化なので、
`RunWith` が動くより前に終わっている。

## どのコマンドが設定ファイルの language を読むか

| コマンド | 設定ファイルの language を読むか | 読む場所 |
| --- | --- | --- |
| `continuo`（常駐プロセス） | 読む | `internal/cli/cli.go` の `runMain` |
| `continuo doctor` | 読む | `internal/cli/cli.go` の `runDoctor` |
| `continuo abandon` | 読む | `internal/cli/cli.go` の `runAbandon` |
| `continuo trust` | 読む | `internal/cli/cli.go` の `runTrust` |
| `continuo prompt` | 読む（`--builtin` を除く） | `internal/cli/cli.go` の `runPrompt` |
| `continuo setup` | 読む | `internal/cli/cli.go` の `runSetup` |
| `continuo init` / `continuo hook` / `continuo statusline` / `continuo version` / `continuo allow-keychain-access` | 読まない | 環境変数から決めた言語のまま出す |

**`continuo prompt --builtin` だけは読まない。**組み込みの指示書は実行ファイルの中にあるので、
設定が壊れている利用者でも読める。**そのために設定を1バイトも読まずに返す。**

**読むコマンドでも、設定を読む段より前に終わる実行は読まない。**
引数の誤り・`--help` の使い方・作業ディレクトリを引けない・設定ファイルの場所を決められない、が当たる
（`continuo doctor` だけは、場所を決められなくても警告を出して先へ進む）。
その実行の文言は、環境変数から決めた言語のまま出る。

**`continuo trust` と `continuo setup` は決め直す場所が違う。**この2つは自分で `config.Load` を呼んでから `useLanguage` で決め直す。
**残りは `useLanguageFromConfig` に読ませ、読めなければ黙って戻る**
（読めないこと自体は、それぞれのコマンドが自分の文言で報告する）。

**`continuo setup` が読むのは、書き換える `WORKFLOW.md` があると確かめたあとである。**
それより前に出る文言は、環境変数から決めた言語のまま出る。
引数の誤り・`--help` の使い方と、`scaffold.CheckUpdatable` が返す失敗の全部
（ディレクトリが無い・ディレクトリでない・`WORKFLOW.md` が無い・symlink である・Status のキーが無い・キーの値を書き換えられない）が当たる。

## 設定を読めないとき、止まるかどうかはコマンドで決まる

**`language` に書けない値を書いたときも、ここに入る。**
`language` の検査（`internal/config/validate.go` の `validateLanguage`）は `config.Load` の中で走るので、
**「設定ファイルを読めない」と「`language` の値が対応していない」は、実装では同じ1つの失敗である。**
言語を決める処理は、どちらでも同じことをする。**環境変数から決めた言語のまま残す。**止まるかどうかを決めない。

**止まるかどうかを決めるのは、それぞれのコマンドである。**

| コマンド | 止まるか | 何がどこへ出るか | 終了コード | 根拠 |
| --- | --- | --- | --- | --- |
| `continuo`（常駐プロセス） | 止まる | 起動の案内を標準出力へ出したあと、起動できない理由を標準エラーのログへ出す | 1 | `runMain`、`internal/daemon/daemon.go` の `Run` |
| `continuo trust` | 止まる | 読めない理由を標準エラーへ出す | 3 | `runTrust` |
| `continuo prompt`（`--builtin` を除く） | 止まる | 読めない理由を標準エラーへ出す。プロンプトの文面は1文字も出さない | 1 | `runPrompt` |
| `continuo abandon` | 止まる | 読めない理由を標準エラーへ出す | 1 | `internal/abandon/abandon.go` の `Run` |
| `continuo doctor`（下の2つを除く） | **続ける** | 見出し語 `設定ファイル` の行を `✗` で標準出力へ出す。残りの検査も行う | 1 | `runDoctor`、`internal/doctor/checks.go` の `checkConfig` |
| `continuo doctor --missing-keys-patch` | 検査を1つも行わない | ファイルを読めないか front matter を切り出せなければ、理由を標準エラーへ1行出す。`language` の値が受け付けられないだけでファイルを読めるなら、差分を標準出力へ出す（足す項目が無ければ何も出さない） | 読めなければ 1、読めれば 0 | `runDoctor`、`runDoctorMissingKeysPatch` |
| `continuo doctor`（接続先を差し替える環境変数の値が不正） | 止まる | 理由を標準エラーへ出す。検査結果は出さない | 3 | `runDoctor` |
| `continuo setup` | **続ける** | 読めない理由を標準エラーへ1行出す。対話へ進む | 対話の結果で決まる | `runSetup` |

**`language` に書けない値を書いたときは、理由の中に書ける値の一覧が入る**
（`validateLanguage` が返すエラーが `"auto"` と資源のある言語の一覧を持つ）。
**この一覧の文は資源から引いていないので、決めた言語によらず日本語で出る**（設計 3-35 の「移し残し」の表）。

**`continuo setup` が止まらない理由。**`continuo setup` は、`continuo init` が `gh` から値を引けずプレースホルダの残った `WORKFLOW.md` に対しても走るコマンドであり、
止めると、その利用者が Status の割り当てを1回も終えられなくなる。

## 環境変数から言語を決める規則

**読むのは `LANG` だけである。**`LC_ALL` と `LC_MESSAGES` は読まない。
設定ファイルの `language` で直接指定できるので、読む変数を増やすと、どれが効いたのかを説明できなくなる。

| `LANG` の値 | 決まる言語 |
| --- | --- |
| `ja_JP.UTF-8` / `ja-JP` / `ja` | 日本語 |
| `en_US.UTF-8` / `en` | 英語 |
| `C` / `POSIX` / 空 / 未設定 | 英語（既定の言語） |
| `fr_FR.UTF-8` のような資源の無い言語 | 英語（既定の言語） |

**文字集合（`.UTF-8`）と修飾子（`@euro`）と地域（`_JP`）は落としてから見る**
（`internal/i18n/i18n.go` の `ParseLocale`）。

## 正の言語と既定の言語は別である

| 何 | どの言語か | 何のためのものか |
| --- | --- | --- |
| 正の言語（`SourceLang`） | 日本語 | 文言を書くときの原文。**訳の無いキーの落とし先** |
| 既定の言語（`DefaultLang`） | 英語 | **設定でも環境変数でも決まらなかったときに出す言語** |

**この2つが食い違っていてよい**（設計 3-35b）。continuo は公開して配るので、
`LANG` を持たない環境で日本語が出ると、読めない人が最初の画面で詰まる。

## 資源が使えないとき

**`internal/i18n/i18n.go` の `init` が panic する。**条件は3つある。どれも、コマンドの処理が1つも走る前に終わる。

| 条件 | panic の文に入るもの |
| --- | --- |
| 埋め込んだ資源のディレクトリか、資源のファイルのどれかを読めない（JSON として読めない場合と、値が文字列でない場合を含む） | 読めなかったファイルの名前と理由 |
| 正の言語である日本語の資源に文言が1つも無い（ファイルが無い場合と、文言ではない項目しか無い場合を含む） | `messages/ja.json` |
| 既定の言語である英語の資源のファイルが無い（中身が空でも、ファイルが在れば通る） | `messages/en.json` |

**終了コードは 2 で、文は標準エラーへ出る。標準出力には何も出ない**
（2026-10-02 に、`init` で panic するだけの Go のプログラムをビルドして実測した。continuo の実行ファイルそのものでは測っていない）。
