# ユースケース: 対象リポジトリを信頼登録する

## 根拠資料

- `docs/plans/continuo_design.md` の「3-33. 信頼の登録は、人間が列挙したものだけを対象にする」（対象は `trust.repositories` だけ。カンバンから集めない。写しを取ってから差し替える）
- `docs/plans/continuo_design.md` の「3-33b. 信頼を渡す前に見せるものと、確かめられなかったときの扱い」（要求内容を確かめられなかったリポジトリは登録しない）
- `docs/plans/continuo_design.md` の「3-6. 起動時の検査を厚くする」（信頼を引く鍵の作り方の3段）
- `docs/plans/continuo_design.md` の「3-22. worktree の置き場所は gwq の規則に合わせる」（clone が無ければ `ghq get` で取る。`--dry-run` では取らない）
- `docs/plans/continuo_design.md` の「4-3. `~/.claude.json` を常駐ループから書き換えない」（書き換えるのは `continuo trust` だけ）
- `docs/plans/continuo_design.md` の「3-59. ファイルの書き換えは一時ファイルへ書いてから差し替える」
- `docs/trying_it_out.md` の「段5. 対象リポジトリを信頼に登録する」（実際に叩いた出力）
- `internal/cli/cli.go` の `runTrust` / `parseErrorExitCode` / `trustInternalErrorExitCode`
- `internal/trust/trust.go` の `Apply` / `readClaudeConfig` / `projectsObject` / `markTrusted` / `writeBackup` / `replaceFile`、`Entry` の `Actionable`、`Report` の `Pending` / `Problems`
- `internal/trust/report.go` の `WriteRequirements` / `writeEntry` / `WriteApplyResult`
- `internal/workspace/trust.go` の `CheckTrustForClonePath`

1件ずつ調べる段（clone のパス・信頼の鍵・信頼の状態・要求内容）は、`信頼登録の対象を調べる.rucm.md` に書いてある。この記述は `INCLUDE USE CASE` で引く。

## 記述の中の語が指すもの

rucm ブロックは、リポジトリを次の3つに呼び分ける。実装の名前は `internal/trust/trust.go` のものである。

| 記述の語 | 実装 | 何を指すか |
| --- | --- | --- |
| 調べられたリポジトリ | `Entry` の `Actionable` が真 | 信頼の鍵まで求められ、要求内容も確かめられたリポジトリ。既に信頼済みのものも含む |
| 未信頼のリポジトリ | `Report` の `Pending` | 調べられたリポジトリのうち、まだ信頼登録されていないもの |
| 調べられなかったリポジトリ | `Report` の `Problems` | 調べられたリポジトリ以外の全部。要求内容を確かめられなかったものも含む |

「写し」は `~/.claude.json.continuo-backup-<時刻>` という名前のバックアップである。continuo は作るだけで、消さない。

## 応答に載るもの

| 応答 | 段 | 出力先 | 何が載るか |
| --- | --- | --- | --- |
| 信頼を登録すると効くようになる設定 | 基本フローの段8 | 標準出力 | リポジトリごとの記号（`✓` 既に信頼済み / `!` 未信頼 / `✗` 調べられなかった）、登録するパス、`permissions.allow`、`permissions.additionalDirectories`、hooks、MCP サーバー、集計の1行 |
| 書き込む前の注意 | 段8 の応答の直後 | 標準出力 | Claude Code のセッションが動いていると書き換えが失われうること。dry-run オプションの指定が無く、調べた時点で未信頼のリポジトリが1件以上あるときだけ出る |
| 結果 | 基本フローの段23 | 標準出力 | 写しの置き場所、登録した項目、既に信頼済みだったので触らなかった項目 |
| 打ち切りの理由 | 終了コード 2 と 3 の代替フロー | 標準エラー | 何ができなかったか |

書き込む前の注意を rucm ブロックの段にしていない。段にすると、その先の経路が全部2倍になるためである（判断ログの 14）。

## 終了コードの分け方

`internal/cli/cli.go` の `runTrust` が決める。

| 終了コード | どんなときに返るか |
| --- | --- |
| 0 | 登録した。または、登録するものが無かった（全部が既に信頼済み、`trust.repositories` が空、使い方の表示） |
| 1 | 人間の手が要るものが残っている。調べられなかったリポジトリがある、書き込んだのに確認できなかった項目がある、`--dry-run` で未信頼のリポジトリか調べられなかったリポジトリがある |
| 2 | 引数の指定が誤っている |
| 3 | `continuo trust` が動けなかった。設定ファイルを読めない、ホームディレクトリを引けない、`~/.claude.json` を読み書きできない、応答を書き出せない |

## 段4・段5 の検証が偽になる理由

どれも、1件も調べずに、標準エラーへ理由を出して終了コード 3 で終わる（代替フロー `調査を始められない`）。
`internal/cli/cli.go` の `runTrust` と `internal/trust/trust.go` の `Plan` が、この順に確かめる。

| 段 | 理由 |
| --- | --- |
| 4 | いまいるディレクトリを引けない（設定ファイルを探す場所が決まらない） |
| 4 | 設定ファイルのパスを決められない |
| 4 | 設定ファイルを読めない、または front matter が検証を通らない |
| 5 | ホームディレクトリを引けない |
| 5 | ホームディレクトリが絶対パスでない |

## 段にしていない打ち切り

`internal/trust/trust.go` の `Apply` は、変える項目が1件以上あると決まったあと（段15 の真）、写しを取る前に、書き戻す JSON を組み立てる。
組み立ての関数（`internal/trust/claudeconfig.go` の `marshalIndent`）は誤りを返す形になっていて、返れば標準エラーへ理由を出して終了コード 3 で終わる。
**この誤りへは到達しないので、段にも代替フローにもしていない。**誤りが返るのは、キーを JSON の文字列に直せないときと、値が JSON として正しくないときである。
キーは Go の文字列なので必ず直せる。値は、段14 で JSON として読めたものか、continuo 自身が作ったものしか入らない。
