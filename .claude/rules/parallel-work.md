# 並列で進める

## 絶対条件：指示が無いときは、workflow と git worktree で並列に進める

**人間が「これをやれ」とだけ言ったときも、既定で並列にする。**
**「並列にしてよいか」を訊かない。**

| 何 | どうするか |
| --- | --- |
| **作業の場所** | **issue ごとに git worktree を1つ作る。**本体では作業しない |
| **調査・レビュー・実装** | **Workflow か Agent で並列に走らせる** |
| **自分がやること** | **設計を書く / 結果を検査する / 人間へ報告する** |

---

## 直列にしてよいのは、依存があるときだけ

| 何 | 並列にできるか |
| --- | --- |
| **別々の issue** | **できる。**worktree を分ける |
| **同じ issue の設計 → 実装** | **できない。**設計が終わらないと実装できない |
| **同じファイルを触る2つの作業** | **できない。**片方の成果が消える |

**「同じファイルを触るか」は、着手の前に確かめる。**
**触らないなら並列にする。**

---

## 絶対条件：同じ issue の中では、レビューと修正を同時に走らせない

**この節を、下の「よくある間違い」より先に読むこと。**
**下の節を「レビューと実装を並列にしてよい」と読み違えた事故が実際に起きた**（2026-09-05）。

**並列にしてよいのは、別々の issue の作業だけである。**

| 何と何 | 並列にできるか | なぜ |
| --- | --- | --- |
| **issue A のレビュー と issue B のレビュー** | **できる** | 触るものが違う |
| **issue A の修正 と issue B の修正** | **できる** | 同じファイルを触らないことを確かめてから |
| **issue A のレビュー と issue B の修正** | **できる** | 同上 |
| **同じ issue のレビュー と、その修正** | **できない。絶対にしない** | **レビュワーが見ている物を、レビュー中に書き換えることになる。**返ってきた指摘が、もう存在しない版に対するものになる |
| **同じ issue の設計 と 実装** | **できない** | 設計が終わらないと実装できない |

**「レビューを待つ間に手が空くから、その issue の実装を進めておこう」は禁止である。**
**手が空いたら、別の issue を進めるか、何もしない。**

**2026-09-05 に実際に起きたこと。**設計レビューの7回目を回している同じ turn で、
**同じ issue の実装を worker へ渡した。**

ユーザー指摘: **「なんでこんなことをしたんだ。ルール違反だし、普通に考えてもレビューしながら修正するのはおかしいだろ。」**

---

## よくある間違い

**この節が言っているのは、次の1つだけである。**

> **複数の issue のレビューが返ってきたとき、その修正を1つずつ順番にやるな。**

**「同じ issue のレビューと修正を同時にやってよい」という意味ではない。**
**それは上の絶対条件が禁じている。**

**2026-09-01、3つの issue を並行して進めていたが、
レビューは並列に回し、その結果を1つずつ順番に直していた。**
**issue A を直している間、issue B と issue C は止まっていた。**

ユーザー指摘: **「まさか直列に作業するつもりじゃないよね?」**

**直すべきだったのは、issue B と issue C の修正も同時に走らせることである。**
**issue A のレビューが返る前に issue A の実装を始めることではない。**

---

## 走らせる順番

1. **いま走らせられるものを全部走らせる。**ただし**1つの issue からは1つだけ**
2. **その間に、自分にしかできないことをやる**（結果を検査する・人間へ報告する）
3. **返ってきたものから順に処理する**

**全部が返るのを待たない。**

**段1 の「1つの issue からは1つだけ」を落とさないこと。**
**issue A のレビューを走らせたら、issue A からはもう何も走らせない。**
**次に走らせられるのは、そのレビューが返ってからである。**

| いま走っているもの | 次に走らせてよいもの |
| --- | --- |
| issue A のレビュー | **issue B の調査 / issue C の実装**（別の issue） |
| issue A のレビュー | **issue A の実装 ← これは走らせない** |
